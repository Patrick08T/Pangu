# 运行契约与验收样本

## Perforce 来源边界

`perforce` 模块仅依赖 `diagnostic`，负责受控 P4 CLI、来源快照、平台 Client 和待审核 shelf。`workspace` 允许依赖 `perforce`，负责将固定已提交基线导入私有 Git、复用检查点、导出增改删及持久交付记录；`scheduler` 允许依赖 `perforce`，将只读检查与交付派到绑定 Worker。Agent 不获得 P4 凭据或额外操作权限。

项目必须显式指定 `git` 或 `perforce`。历史 Git 项目由迁移赋值。Perforce 续跑继承最初已提交基线与映射；交付差异相对于该起始基线，包含复用成果。模板 Client 仅用于读取，不在其日常工作区同步或整理更改。待审核 shelf 与关联独立 Client 不进入自动过期清理；无交付运行清理前核验并删除自有 Client。元数据包含无法可靠解析的非 UTF-8 路径时明确拒绝，不替换文件名。

## 可视化定义

控制台通过画布和表单生成工作流，不要求用户编写配置文件。`Flow.editor` 保存节点显示名称、位置及画布视图，随草稿和发布版本持久化，编译执行时忽略。未完成草稿允许零节点和暂时失效的连线引用；草稿仍校验结构、预算、输入字段结构及同工作空间 Agent 版本引用。发布时完整校验 DAG、条件、审批、Codex 工作区限制及已声明结构的字段路径与类型。没有声明输出结构的引用在运行时校验。发布版本不可变，定时任务仍固定版本。

## 状态和查询

### Agent 交接契约

节点 `handoff` 包含 `objective`、`inputs`、`deliverables`、`acceptance`、`failure_handling` 五项文字。每项最多 4096 UTF-8 字节。未完成草稿允许缺项或空白；发布共享 Agent、工作流以及首次接受试运行、正式运行、人工重跑、返工和 Cron 触发时必须完整。发布版本与运行快照保存原文，执行时传给 Eino 或原生 Codex，不缓存或补写历史配置。

升级前已接受的请求可按原幂等键恢复；同一运行的节点自动重试/重启恢复不视为新任务。旧发布版本仍可读取，首次新任务必须使用补齐契约后发布的新版本。缺少契约且未创建提交回执的 Cron 触发记为 `skipped`，原因指出缺项，同时释放对应活动槽；更新计划后可继续触发。不能因缺契约终结已关联提交回执的触发。

契约描述协作要求，不扩大任务资料授权、工具、预算或文件权限。文字验收标准通过指令传递；结构化输出继续由 `output_schema` 校验，交付质量仍需证据或人工核验。

结构化结果只通过节点输出的 `text` 保存和传输一份 JSON 原文，不重复携带 `data`。条件判断和字段映射直接解析该原文，检查点恢复、返工和输入预览采用相同路径。正文及包含运行 ID、报告引用和 JSON 转义的完整输出均不得超过 16384 字节；超限诊断分别列出正文大小、序列化大小和上限，不能以正文长度代替传输长度。校验不得裁剪业务字段或将无效结果转为成功。

### Agent 草稿试运行

`POST /catalog/{id}/draft/preflight` 只诊断，不提交模型任务；`POST /catalog/{id}/trials` 接受 `{revision,input}` 并固定服务器当前草稿。`GET /catalog/{id}/trials?offset=0` 分页返回来源修订和请求回执，正文通过既有运行接口查询。草稿试运行不创建发布版本，也不能用作工作流或 Cron 的固定引用。

提交的 `Idempotency-Key` 为 `Unix毫秒时间戳.UUID`。同项目、操作者、对象、修订和输入返回同一回执，内容变化返回 409；接受后草稿更新或归档不改变回执和快照。89 天重试窗口到期返回 409，旧记录清理后也不会重新派发。键时间超前超过 5 分钟时拒绝。首次接受的项目运行权限在身份锁下重新验证，修订检查、提交快照和草稿来源关联同事务落库；后续复用既有派发与对账路径。

### 运行状态

| Hatchet | Pangu | 含义 |
| --- | --- | --- |
| QUEUED | queued | 已接受，等待调度 |
| RUNNING | running | 执行中，含等待子任务和持久恢复 |
| COMPLETED | succeeded | 编排成功结束 |
| FAILED | failed | 重试耗尽或不可恢复失败 |
| CANCELLED | cancelled | 调度已取消；文件清理和执行器停止证据单独确认 |
| 未知值 | unknown | 不推测成功或失败，保留诊断 |

取消请求是独立意图。发送取消成功只返回已接受，未证实执行器停止前不得把业务运行标为安全终止。取消和重跑路由以 OpenAPI 为准。

`GET /runs` 支持 offset、limit（1–100，默认20）、status、since、until（RFC3339）。首屏默认最近90天，并返回固定时间边界，后续页沿用这些边界。按产品提交时间、运行 ID 降序分页；状态筛选在当前页应用，空页仍可能有下一页。执行状态实时变化，调用方按 ID 合并并支持刷新。查询只包含当前命名空间及授权项目的根运行。

`GET /runs/{id}` 返回产品字段，节点按 node_id 排序。真实节点 attempt 从 1 开始，Hatchet retryCount 加1；跳过和复用节点为0，其 UUID 是稳定的产品显示标识，不代表新建 Hatchet 任务。不把模型回复当作工具执行证据。不返回凭据或原始调度输入。新提交可能短暂404，应按 Location 重试查询。

自动重试/重启恢复沿用同一运行与节点身份；人工重新运行必须新建运行，固定原始定义、输入及 Git 基准，并链接来源运行。基准不存在时拒绝重跑，不取最新分支。

检查点返工使用 `POST /runs/{id}/fork`，与整次重跑区分。选中成功的 Codex 文件检查点，复用此前条件、输入及定义相同的串行成功前缀，支持其中的 Eino 研究报告；跳过和最新失败节点不复用；报告复制校验项目、来源与正文哈希。并行前缀尚不支持人工返工。定义变化使该节点及后续失效，全局输入改变使全部失效。记录父运行、选中节点、原始基准、实际复用节点与请求摘要；旧历史不覆盖。对返工运行再做整次重跑时，从最初 Git 基准执行全部节点。来源清理后，已接受返工仍可在自身幂等记录保留期内以原键/原输入/原发起人找回。

条件 `when` 只允许布尔或字符串精确匹配，字段来源为 `$input` 或直接上游的结构化输出。未命中时生成 `skipped` 产品节点，不派发 Agent；任何直接上游跳过会使后续依赖节点跳过，不提供自动合并互斥分支的语义。

人工审批通过 Hatchet 持久事件等待恢复，不设过期时间。节点配置 `approval: {source_node, revision_nodes}`，来源为直接上游结构化报告，修订集合为只读 Codex 规划祖先并包含来源。审批节点独占执行层，修订集合必须覆盖已完成的受影响节点，避免旁支保留旧计划。运行进入 `waiting_approval`（待审批），暂停后续派发且不启动模型进程；逐项批准后继续，驳回或撤回则结束，等待期间仍可取消。Worker 重启后恢复同一审批，执行前重新核对权限、完整内容摘要与检查点；不因等待时间放宽这些核验。已终结的历史过期审批保留记录，不自动复活。人工采纳必须来自飞书会话并绑定当前产物摘要，API Token 不能代填。专用交付先经过只读规划审批，再实施与只读审查；ZIP 要求实施与审查真实验证成功、运行确认停止、当前产物经人采纳。普通产物下载用于检查，不代表业务验收通过。

`review` 包含标题、摘要、审核项与纠偏回应，每项具有稳定 ID、分组、标题、建议、理由、报告内依据引用与任务 ID。人工决定单独保存为 `items`，结论为 `accept/revise/reject`，无默认同意；整体 `approved` 必须覆盖全部项且无纠偏或未解决回应。`changes_requested` 将运行置为 `revising_plan`，携带经过身份核验的 `review_feedback`，按依赖顺序修订配置中的角色。保留研究结果，更新所有修订输出后创建下一轮冻结审批；新一轮须重新逐项确认。整体意见以 `overall` 回应。修订失败不得回退旧计划实施。

每轮唯一标识为 `(run_id,node_id,round)`，通过 `previous_id` 保留历史。`GET /approvals` 返回当前项目的分页摘要，指定运行可查看历史；`GET /approvals/{id}` 返回审核详情与运行状态，`PUT` 校验完整结构化决定。页面分别位于 `#/approvals` 和 `#/approvals/{id}`。子任务查询完整分页，节点历史按逻辑 ID 及创建时间降序排列，最新尝试未成功时不能使用旧成功输出。审批正文清理时同步删除逐项意见。

临时输入、日志和产物保留30天，运行/请求摘要保留90天，审计保留180天。Hatchet core/OLAP 统一配置720小时；产品库独立保存确认终结的无正文摘要。远端明细到期后，详情返回摘要和 `logs_expired`，事件返回410；无法确认的状态为unknown，不能推测成功。发布配置不随运行清理。

## 客观验收样本

选择 Pangu 自身作为第一个真实项目。在独立 clone 内新增 `docs/agent-acceptance.md`，内容必须为中文且包含“任务目标”“验收标准”“风险”三个标题；不得修改任何其他文件。

编排：Eino 产品经理整理简短目标 → Codex 创建文件 → 只读验证。客观验收：Git 差异只有该新文件，文件 UTF-8 可解码，三个标题均存在，源仓库工作区与 HEAD 未改变，`go test ./...` 退出码为0。最终报告必须引用真实命令退出码与文件摘要，不能由模型声称测试通过。

模型供应商、费用上限和真人采纳结果未配置前，此样本只作为可执行验收规范，不计为真实完成。

## 行为追踪与节点调试（2026-10-28）

`policy` 只包含 `retries`；旧的 `timeout_seconds`、`tool_calls` 不再是有效请求字段，导入配置需删除它们。审批配置不接受 `timeout_seconds`，必须填写审核报告来源和修订节点。未设置 `budget` 时不施加默认调用上限；设置后按原来的显式额度原子预留，纠偏重跑同样计入预算。

`GET /runs/{id}/debug` 返回持久暂停状态、单步许可、版本和活动尝试数；`POST` 接收 `{action: pause|resume|step, revision}`。控制需要当前项目运行管理权限与会话 CSRF，写入时重新授权并审计。版本过期、已取消、终态或单步时仍有活动节点返回 409。

暂停只阻止尚未开始的节点尝试，已开始的执行继续完成。单步放行一个就绪节点尝试；若失败需重试，重试也等待下一次单步或继续。根派发与尝试开始共同检查持久闸门，取消仍可终止进程树。重放不新增调度调用序列；暂停等待占用当前 Worker 槽位，不是操作系统挂起。人工审批、依赖和分支条件继续生效。

`GET /runs/{id}/trace` 支持 `node/kind/status/after/before/limit`，按递增提交序号倒序分页；使用 `next_before` 读取更早记录。界面每 2 秒刷新最新页。`trace.ndjson` 导出相同筛选下的全部记录，开始后的新增记录不纳入；末尾 `export_error` 表示导出不完整。

事件含运行、节点、尝试、span/父 span、开始/结束、模型请求摘要、工具参数/结果、耗时、状态和错误。节点输出正文最多保存 16384 字节，以覆盖有效范围内的成功或失败结果；其他输入/输出/错误仍各最多 8192 字节，真正超限有截断标记。入库前脱敏，不采集认证头或模型内部思维链。节点停止后，缺少完成回执的 span 标记为中断，不能推断成功或外部副作用已回滚。追踪正文按运行保留期清理，晚到事件不得复活正文。

## 完整报告与检查点上下文

只读 Codex 节点可声明 `report_schema` 校验完整 JSON 报告，`output_schema` 仅声明从报告中选取的标量摘要。完整正文上限 1 MiB，由平台与成功文件检查点在同一事务中保存到现有报告存储；节点传输仍限制 16 KiB，携带报告 ID 和 SHA-256。仅 `summary` 展示摘要可截短至 1 KiB，其他控制字段及完整报告、任务和验收条件保持原文。报告引用与正文哈希不一致时拒绝交接。

审批模块允许依赖 research 模块读取直接上游原始报告。审批主体展示并绑定完整正文，执行消费审批时重新读取并核对正文，不缓存报告；普通 JSON 上游与研究正文的读取格式必须区分。审批后的正文变化不能沿用原批准。

平台在 Codex 执行前校验尝试目录、运行项目、Worker、已登记检查点、祖先关系及干净工作区，将 `revision` 中的起始基线、运行基线、当前检查点及相对起始基线的文件差异传给模型。提交号变化不表示文件发生变化。审批仍绑定实际检查点，运行时版本上下文不参与改变已冻结的审批输入。

## 多方案人工审核（2026-10-29）

存在多方案的审核项提供 `selection_mode`、`options`、`recommended_option_ids`、`planned_option_ids`、`recommendation_reason`。互斥方案单选，可组合方案多选；推荐不自动勾选，不代表授权。没有真实备选方案的审核项无需提供这些字段。

逐项答案使用 `selected_option_ids` 保存审核人选择。后端校验方案引用、重复和互斥约束，选择与当前计划不同时，只能提交纠偏，先修订再复审；允许有明确变更选择时省略重复文本，也允许清空选项后只提交文本纠偏。多选集合顺序不影响幂等性。选择及原方案通过 `review_feedback` 交给修订角色，所有记录继续绑定本轮不可变报告。历史冻结报告不补写或猜测备选方案。

## 迭代闭环与版本接续（2026-10-29）

运行的 `outcome` 独立于引擎状态。所有终端节点明确 `iteration_complete=true`、`ready=true`、`status=complete`，且引擎成功，才显示业务验收通过；缺失、跳过、部分完成或引擎失败不能推导通过。发布后接续的原运行显示 `continued` 并链接后续回执，历史验收正文不改写。

每个 Codex 节点在执行前从原始数据库采集 `platform_evidence`，索引位于独立 clone 的 `.git/pangu-evidence/manifest.json`。按职责读取冻结快照、审批与消费、文件检查点、实际尝试、工具动作、报告和用量；附来源运行、采集时间、哈希、缺失与截断限制，执行后检查未被修改。直接上游引用仍校验归属和哈希，正文按需从证据文件读取。`GET /runs/{id}/evidence` 受项目读取权限和保留期约束；`path` 仅接受索引中精确路径。

审批配置 `execution_plan=true` 时，来源报告须包含 `tasks` 和 `execution_plan:{changes,assignments}`。任务一对一分配到真实后续节点，每个保留节点均须有分配。允许调整后续节点、依赖、任务和已发布 Agent 版本；不改写已完成规划，不删除审批节点。平台从原始发布版本计算差异，在审核页增加保留项 `platform-execution-graph`。用户调整后先修订再复审；批准包含图变更时还需要共享目录管理权限。

发布新版本、保存接续请求及消费原批准在同一事务中完成，重复操作返回原回执。草稿修订冲突会明确拒绝，不覆盖他人更新。子运行核对获批内容、版本和复用成果后继承授权，展示原审批来源；历史运行保持原定义。显式调用预算累计来源链消耗，取消请求传递到已绑定和待派发的接续运行。仍可运行的接续链所需用量记录不因 90 天清理丢失。

只读完整报告节点可返回 `evidence_blockers`，每项含唯一 `id`、`owner`、`reason`、`resolution_condition`，最多 8 项。缺关键证据时创建不自动过期的待审批事项，暂停派发；补证决定只触发同一节点只读复验，用户点击不等于验收通过。其他成果及纠偏保留；代码缺陷应进入既定修复路径，不能用补证替代修复。无变化检查的复用由角色核对来源及适用性，平台未实现自动跳过全部模型复验。

## 循环块与条件入口（2026-11-05）

`loops` 把无环成员图作为重复执行块；成员不能重叠或嵌套，只使用无条件、无审批的 Codex 节点。全部写入步骤先于只读质量门，质量门按顺序执行并返回 `passed` 与非空 `summary`。任一门不通过则保留补丁和失败报告进入下一轮；同轮同代码的全部门通过后退出。无默认轮数上限，取消、显式预算和执行异常仍生效；不提供任意有向回边或自定义 break。

执行循环前核对所有成员的块外依赖。任一块外依赖已被条件跳过，则整块及其依赖下游按跳过处理，不执行任何成员，不生成轮次或验收通过结论。普通质量失败 `passed:false` 仍触发返修，不能按条件跳过。块内禁止人工审批与补证等待，部署等不可安全重复的动作留在块外；下游只能从最后质量门接收当前轮结果。

现有市场迭代与后端交付在代码修复阶段使用独立质量门，累计 OCR 和本地回归失败后只重跑修复块。市场的补证与最终产品验收、后端的本地部署与部署后 QA 保持在循环外；其失败不会自动回跳代码修复块。质量门的 `passed` 只代表该门范围通过，不能取代最终验收。

### Perforce 本地工作区（2026-10-30 后续确认）

Perforce 项目必须绑定 Worker 上现有 Client 的 Root/AltRoot，通过 source 字段登记；任务直接在 source 与 scope 组成的目录执行。管理员可在项目页或 PATCH /projects/{id}/workspace 核对并保存既有项目绑定，未结束或待派发任务期间禁止改绑。

新运行以本地现状为起点，执行前后快照保存在平台目录，包含已有未提交修改。本轮新增打开文件进入本轮 changelist，已打开文件保持原清单归属；失败或取消保留现场，不回退文件。中断恢复先补齐旧尝试的快照和 P4 跟踪，未确认进程停止时不启动新操作。带成果复用的续跑要求当前内容与选定检查点一致；不一致时新建运行，不重置本地目录。

交付只 shelve 本轮清单，原清单的修改单独提示。运行后的额外修改或混入清单的无关文件会阻止交付。Git 项目继续原独立副本规则，旧隔离 P4 运行保留原历史交付路径。完整边界见 docs/superpowers/specs/2026-10-30-Perforce本地工作区执行-design.md。
