# 原生 Codex 执行器

使用本机 Codex CLI 的 `codex exec`，与 Eino 节点混合编排。用户已确认允许在 Worker 指定的项目目录内读写，继续采用 TDD 和 Codex 原生 Agent 审查。

## 接口与边界

- 节点必须指定 `executor: "eino"` 或 `"codex"`；拒绝缺失或未知值。Eino 必须指定模型，Codex 可省略模型以采用 CLI 配置。
- Worker 每次执行读取 `PANGU_CODEX_BINARY` 与独立 `PANGU_CODEX_HOME`，两者均为绝对路径；工作目录由服务端分配。项目源目录由管理员登记，运行开始时固定 Git 基准，节点尝试使用独立工作区。不接受 JSON 中的程序路径、命令行、工作目录或凭据。
- 原始指令、用户输入和直接上游结果通过标准输入传入 Codex；使用参数数组启动原生程序，不通过 Shell 拼接。
- 使用 `workspace-write`（只读模板使用 `read-only`）沙箱及 `never` 审批模式。Windows 显式启用官方 `unelevated` 沙箱，避免默认将可写请求降为只读；不会覆盖只读模板。不启用沙箱绕过选项，专用登录由管理员配置；仅继承操作系统必需环境，禁止复用个人 Codex 配置或工作区内配置。沙箱能力仍受平台支持范围约束。
- Codex 使用独立 Hatchet 任务，取消命名空间固定并发上限。独立运行可并行；同一运行的文件操作仍由检查点锁串行保护，Worker 槽位表示资源容量。
- 节点只配置 0–2 次重试，不再配置执行时限。Hatchet 执行和排队 duration 使用最大值，SDK 按秒保存，约 292 年。完成节点不重新执行；未完成节点从已发布检查点创建新尝试，不续接 CLI 会话，失败尝试的文件不发布。
- 必须使用 [原生受控构建](../runtime/codex/README.md)，记录模型和工具的真实开始、结束、参数、结果、耗时及父子关系。取消 Pangu 工具计数器和 30 秒 watchdog，原生长命令会话可以继续轮询；保留直接工具模式和权限限制。认证、参数及工具越权错误不重试，429 可按节点策略重试。
- 最终输出仍限制为 16 KiB。超时、退出失败、无最终输出或超限必须返回错误。
- 取消执行时清理子进程；Windows 使用 Job Object，使 Worker 退出时结束所属进程树。Linux 取消时清理进程组，但强制杀死 Worker 后外孙进程的存活不在当前保证内。
- Cron 固定已发布的流程版本，修改模板或新发布版本不改变既有绑定；人工重跑固定原定义、输入与基准。基准或输入到期时拒绝新重跑，同一幂等键仍返回保留期内的原回执。

## 验收

1. 校验执行器、分派、模型规则，拒绝任意执行路径字段。
2. 使用可控子进程验证参数、标准输入、最终输出、配置重新读取和错误处理，不调用收费模型。
3. 验证取消会结束进程树；Windows 验证宿主被终止后子进程退出。
4. 真实 Hatchet 验证 Codex 节点串行、独立重试、上下游传递和查询。
5. 使用本机已登录 Codex 在临时 Git 项目完成一次文件写入并验证内容，保持真实项目文件不受测试影响。
