# Pangu 首版最小链路

## 已确认范围

使用 Go、Hatchet、Eino，提供 API 和 JSON 编排，不做管理后台。全部文件仅使用 Git，豁免 P4。测试先行，实现后使用 OpenCodeReview 审查。

每个 Agent 节点必须由 Hatchet 独立调度、重试和恢复。使用固定的持久编排任务接收完整 JSON，并派生独立 Agent 子任务；Eino 只在子任务中访问模型。编排逻辑根据任务输入和已持久化的结果确定执行顺序。

## 接口与执行边界

- `POST /runs`：提交包含 `input` 与 `nodes` 的 JSON，返回运行 ID。
- `GET /runs/{id}`：读取 Hatchet 的状态、输出及子任务信息。
- `POST /crons`：提交名称、UTC 五字段 Cron、完整编排，返回定时任务。
- `GET /crons`、`DELETE /crons/{id}`：查询和停止定时触发。
- `GET /healthz`：进程存活检查。

节点包括 ID、描述、指令、模型名称和依赖 ID。采用无环图；每一层并行，下一层等待上一层完成。节点失败由 Hatchet 重试两次；重试耗尽后停止下游，已完成节点由持久事件记录恢复。节点内模型调用可能重复，不承诺外部副作用恰好执行一次。进程重启后的恢复依赖 Hatchet 服务及其数据库可用。

模型凭据从 Worker 的环境变量读取，不放入编排或 Hatchet 输入。运行使用提交的完整定义作为不可变输入；不维护配置缓存，不持久化额外的本地运行数据库。Cron 保存提交时的定义，修改定义需删除并重新创建 Cron。首版 Agent 支持自定义模型、指令和依赖上下文，不提供任意代码执行和工具插件管理。

API 仅监听 `127.0.0.1:8080`，面向本机受信用户；对外服务需要独立认证网关。最多 32 个节点、请求体 256 KiB；仅接受合法且完整的 JSON，拒绝未知字段。运行及 Cron ID 使用 UUID。

## 验收条件

1. 拒绝空图、重复节点、非法 ID、缺失指令/模型、重复/未知依赖和循环依赖。
2. 非拓扑顺序的 JSON 也能得到稳定分层；独立节点并行提交，依赖结果只传给对应下游。
3. 每个节点创建 Eino Agent，传入自定义指令、用户输入及上游输出；模型失败原样传播到任务重试层。
4. API 提交正确输入；非法 JSON 和 ID 不调用后端；后端故障返回明确的服务错误。
5. Cron 校验五字段 UTC 表达式并将完整定义交给 Hatchet；提供列出、删除操作。
6. 真实 Hatchet 集成验证单节点失败后独立重试、完成节点不重复执行、运行结果可查询；本地无法连接时必须显式标记未验证。
7. `go test ./...`、`go vet ./...` 和构建通过；按用户最终指示使用 Codex 原生 Agent 审查。
