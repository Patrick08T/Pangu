# Pangu

Pangu 是一个以 Go 为主要开发语言的 Agent 工厂，目标是支持自定义 Agent、工作流编排与定时任务。

当前状态：已确认采用 **Hatchet + Eino**。仓库尚未包含可运行的服务，首版交互方式与实现范围正在确认。

## 技术选型

| 组件 | 职责 |
| --- | --- |
| [Hatchet](https://github.com/hatchet-dev/hatchet) | 定时触发、工作流依赖、任务分发、重试、并发控制和运行记录 |
| [Eino](https://github.com/cloudwego/eino) | 自定义 Agent、模型调用、工具调用及 Agent 内部协作 |
| Pangu | 管理 Agent 和编排定义，将用户发布的配置交给执行层运行 |

Hatchet 与 Eino 通过 Go 执行任务接入。本项目不依赖现成的官方 Eino 专用适配器，接入实现仍需验证。

## 产品目标

- 创建自定义 Agent，配置模型、提示词及允许使用的工具。
- 将 Agent 组成可复用的工作流。
- 通过手动调用或定时计划触发执行。
- 查看运行状态、节点结果及失败信息。

第一版采用 API 与配置文件，还是同时提供网页与可视化编排，尚待确认。Hatchet 的运行面板不直接代替 Pangu 的编排编辑器。

## 执行边界

工作流引擎管理任务之间的执行顺序；Eino 在普通 Go 任务中执行 Agent。模型请求、数据库访问及外部工具调用不直接放进要求确定性重放的编排逻辑。

外层任务恢复不意味着 Eino 内部每次模型调用都会自动恢复。实现时需要明确恢复粒度，并处理外部工具的幂等性与重试导致的重复调用。

参见 [Hatchet 持久任务约束](https://docs.hatchet.run/v1/durable-tasks)。

## 定时任务边界

本次调研的 Hatchet 官方文档说明：

- Cron 使用 UTC。
- 服务停机期间遗漏的 Cron 默认不会自动补跑。
- 定时触发表示任务入队时间，实际开始时间受并发限制、限流及系统负载影响。

Pangu 的时区展示、漏跑处理和重叠执行策略需要在实现前明确，不能假定框架已经提供所需的全部行为。

参见 [Hatchet Cron 文档](https://docs.hatchet.run/v1/cron-runs)。
