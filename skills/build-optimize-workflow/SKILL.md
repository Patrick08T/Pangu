# Workflow 构建与优化

以可验证的业务结果为目标。让人定义目标和授权边界，让 Agent 在边界内执行并提出改进，让独立评估决定修改是否生效。默认用中文说明，按用户语言调整。

## 入口

1. 判断任务是新建、诊断、实现、评估还是优化现有系统。延续已有决策，不为常规可逆工作重复请求确认。
2. 检查已有项目指令、代码、依赖版本、提示词、工具定义、真实轨迹和评估。区分 Codex CLI/SDK 的完整 Agent 循环与底层模型 API，不根据框架名称猜架构。
3. 用户要求实现时，完成代码与相关验证，不止交付建议。没有可访问代码时，提供接口、最小实现设计和待验证假设；明确未实测，不虚构改动。
4. 只询问真正阻塞的信息，同时推进独立工作。常规命名、结构和可逆实现选择自行决定。
5. 按需读取：
   - 实现交接、状态、工具和预算：[contracts.md](references/contracts.md)。
   - 诊断、实验、评估和自优化：[evaluation.md](references/evaluation.md)。
   - Eino、Codex 和性能取证：[eino-codex.md](references/eino-codex.md)。
   - 制定方案或记录实验：[workflow-spec.yaml](assets/workflow-spec.yaml)。这是设计模板，不是可执行的 Eino 配置；按需复制并删减字段。

## 构建流程

### 1. 定义成功
记录输入范围、数据源、可检查结果、失败与证据不足行为、质量指标、时间/费用/调用预算、允许副作用和发布范围。
允许正确输出“证据不足”，不要强迫每个案例找到根因。结果和过程分别检查，不要求复现唯一工具路径。
缺少阈值时提出暂定值并标记假设，不声称用户已接受或据此扩大上线权限。

### 2. 建立基线
从真实任务构建小批代表性案例：正常、复杂、无异常、缺数据、版本错误、误导性相关性。保存获准的输入/工具结果快照，分离开发集与受保护验收集。
优先采用“确定性准备 → 单分析 Agent → 校验”，或以现有系统为对照。仅在存在清晰信息边界、独立验收任务或并行收益时拆分 Agent。

### 3. 定义节点和控制权
给每个节点定义输入、输出、工具、状态读写、超时、重试、结束条件和失败去向。
用代码完成字段验证、时间对齐、版本选择、计数、去重、缓存和存储；用 Agent 完成假设、语义判断、相关性选择和动态取证。
让一个明确执行层拥有当前任务的规划和停止权；嵌套 Agent 时划分互不重叠的职责、子任务验收和共享预算。
只并行无依赖节点；合并时保留冲突和反证，不以多数投票替代证据。

### 4. 实现上下文和约束
通过版本化契约交接事实、假设、反证、缺口、证据引用、查询记录和预算。人定义协议，Agent 选择相关内容，程序保证必需字段、来源和范围。
不默认传递全部聊天记录，也不只传不可追溯的摘要。保留按需读取原始证据的途径与上下文不足回退机制。
在工具服务/执行器中强制权限、窗口、预算与参数校验；提示词不能作为唯一硬约束。
定义取消、超时、重复执行、恢复与副作用语义；重试不能默认重新执行所有步骤。

### 5. 接入观测和验收
记录可观测输入输出、工具参数/结果引用、耗时、错误、预算、版本和路由。保护敏感信息，不要求或保存模型隐式思维链。
结合确定性校验、真实结果测试、校准的语义评估和人工抽查。结构化输出仅保证形状，不能证明事实正确。
有限修正循环应返回具体缺陷和相关证据，跨轮次共享预算；达到上限则输出部分结果与未解决项。

## 优化流程

1. 找到首个可观察失败点，区分输入、工具、上下文、推断、编排、验收和运行时问题。未证实原因标记为假设。
2. 提出可证伪的修改假设、预期收益、潜在回归和对照条件。先修数据/工具，不默认堆提示词或增加 Agent。
3. 保存基线和候选版本，每轮修改一个主要因素或不可分割的修复组。锁定模型、数据快照、配置和预算，记录不可控变化。
4. 让优化 Agent 在独立分支/配置版本修改并运行开发评估；不能改受保护评分器、隐藏答案、验收阈值或权限以获得通过。
5. 在相同案例比较质量、无依据结论、完成率、重复查询、耗时和费用；重要案例重复试验，样本不足则报告不确定性。
6. 通过验收且在既有发布授权内，影子运行或小流量发布并设置回滚。没有发布授权时，完成可审查候选和测试，标明未上线。
7. 把新失败加入开发/回归案例，保留独立验收集，定期由负责人审查代表性。仅在证据支持时采用改进。

## 自主修改边界

| 修改 | 执行方式 |
|---|---|
| 当前任务假设、取证顺序、相关上下文选择 | Agent 在固定范围和预算内自主调整 |
| 提示词、检索策略、摘要、交接实现、工具描述 | 生成候选，经回归后采用 |
| 节点、并发、模型、恢复逻辑 | 验证资源/状态语义，再比较端到端收益 |
| 权限、范围、总预算、评分标准、自动发布范围 | 遵循明确授权；超出范围提出具体修改与理由供负责人决定 |

不让生产任务 Agent 为通过验收修改自己的规则。不要机械要求每次改动人工批准：已授权低风险范围可通过预设门槛自动放行，优化器不能自行扩大该范围。

## 交付

按规模提供：架构或失败证据、最小改动、节点/交接契约、实际实现、验证结果、剩余不确定性、上线/回滚状态。
以测量与证据证明改进，不以文风专业作为正确性指标。没有运行环境时明确“设计完成，端到端效果未验证”。
遵循当前环境的文件保存和项目规范，不假定特定持久化服务或仓库位置。
