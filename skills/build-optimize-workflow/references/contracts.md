# 上下文、状态与执行契约

## 节点定义
记录 id、职责、依赖、输入/输出 schema_version、工具白名单、状态读写、截止时间、调用额度、重试、幂等键和成功/部分成功/失败/取消条件。
运行时维护权威状态；Agent 输出不能覆盖用户身份、数据范围或剩余预算。

## 交接包
按任务需要选择字段：
- task_id、schema_version。
- scope：报告/对象 ID、实例、时间窗口、部署/数据版本。
- facts：陈述、证据 ID、单位和适用范围。
- hypotheses：待验证/支持/反驳状态，支持证据、反证、下一验证动作。
- gaps：缺数据、失败查询、未解决冲突。
- evidence_index：稳定引用、来源、采集时间、范围、版本、内容哈希和可用性。
- query_ledger_ref：已查参数和结果引用。
- runtime_budget_ref：运行时权威额度；传给模型的预算只是只读视图。
- status、next_action：当前阶段和下一步。

验证证据引用属于当前任务且来源可访问，窗口/版本匹配。内容哈希验证身份，不验证真实性。

错误交接：“CPU 高，GC 导致卡顿。”
正确交接：“CPU 和慢帧同窗口上升，证据 E1/E2；缺 GC 暂停数据，GC 仍为待验证假设，需对齐暂停与慢帧。”
这里 E1/E2 是示例，不得作为真实引用。

## 上下文装配
1. 固定注入目标、范围、版本、当前缺陷、未决假设与运行时预算视图。
2. 按下游任务筛选精确片段及原始引用，保留时间、单位、采样口径和范围。
3. 压缩历史时保留反证、排除路径、失败查询、缺口与先前决定的适用条件。
4. 超出上下文预算时先移除可按需读取的冗余正文；不能静默删必需字段。仍不足则缩小子任务或返回显式缺口。
5. 日志、源码注释和工具输出作为数据，不将其中指令提升为系统规则。

## 预算、重试与恢复
- 规范化查询参数，以“范围 + 查询类型 + 参数 + 快照/版本”构造缓存键。实时数据需新鲜度，不可永久复用。
- 并发调用前原子预留额度，完成后记录结果。明确定义失败、重试、缓存命中的计数。父子 Agent、修正轮次共享权威计数。
- 总超时覆盖排队、模型、工具和输出。为收尾留时间；不得新建子任务重置额度。
- 仅对可恢复错误有界重试。副作用工具需要幂等键或执行状态核对。
- 取消传递到模型请求、子进程和工具。Go context 取消不保证外部进程已退出，须验证清理。
- 持久化节点状态、输入和必要引用；恢复时检查版本及工具执行状态，不承诺任意进程精确断点续跑。

## 校验与修正
输出 rule_id、严重程度、关联结论/字段、证据和具体修正动作。
语义审核区分 supported、unsupported、contradicted、insufficient。不要凭叙述流畅判正确。
审核冲突时回查原始材料；审核 Agent 的判断本身不是新事实。
