# 评估与受控优化

## 实验记录
记录实验 ID、失败案例与轨迹、修改假设、基线/候选版本、变量、预期影响、潜在退化、冻结配置、评估集版本、重复次数、结果与发布范围。
区分“可能有效”与“已测得有效”；代理指标改善不等于业务成功。

## 评分隔离
- 开发案例可展示完整轨迹和答案；验收样本与隐藏标签置于优化器无权修改/读取的边界。
- 独立评估任务加载候选，受保护版本提供评分器与阈值；仅返回必要聚合及缺陷信息。限制反复试探验收集，避免隐性过拟合。
- 定期补充未见案例，按事故、报告、项目或时间划分，防止同源材料切片泄漏。
- 合成案例可验证边界与接口，但须标注；不能据此声称真实场景准确率提高。

## 指标
| 指标 | 定义与限制 |
|---|---|
| 任务通过率 | 同时满足业务验收与硬约束的任务 / 全部任务；不得丢弃失败与超时 |
| 无依据结论比例 | 无证据支持的可核验结论 / 全部可核验结论；同时检查遗漏和空报告 |
| 引用有效率 | 可解析且范围匹配的引用 / 全部引用；不等于语义支持率 |
| 缺证据处理 | 正确标识真实缺口；不能以全部拒答刷分 |
| 重复查询率 | 规范化键和新鲜度下无新增信息的重复调用 / 全部取证调用 |
| 效率 | 完成率、端到端耗时、工具耗时、调用/token量；费用未知则不编造 |

先满足硬门槛，再比较质量，最后比较质量可接受范围内的速度和成本。阈值来自业务要求或标记清楚的实验假设。
小样本不要滥报 P95/P99；给样本数、重复次数、原始分布或范围。重要案例多次运行，配对比较并说明不确定性，不选单次最佳结果。

## 失败定位顺序
1. 输入：实例、窗口、版本、单位、口径、缺失？
2. 工具：参数、权限、截断、超时、陈旧缓存？
3. 上下文：证据丢失、摘要扭曲、过载、假设变事实？
4. 推断：相关性代替因果、忽略反证、强行根因？
5. 编排：重复规划、依赖错误、状态竞争、没有终止？
6. 验收：偏好文风、规则过窄、标签错误、泄漏？

修最早影响结果的可验证原因；不要用大模型掩盖输入错误。模型切换本身是实验变量。

## 自动优化职责
生产执行器使用固定配置，生成可观测轨迹。离线优化器读取获准开发数据并创建候选。独立评估器运行固定门槛，发布器在授权范围内放行，监测器回滚。
这些角色可以是程序模块，不要求多个 LLM Agent。
优化器不得自行改阈值、删失败用例、读隐藏标签、扩大权限或预算。确需改变目标时建立新的业务基线，不伪装成同目标下的提升。

## 发布与回滚
保存提示词、模型设置、工具 schema、上下文策略、代码和评估版本的映射。
影子运行默认禁用实际副作用；小流量发布遵循既有授权，监测质量、错误、延迟、预算。
提前定义触发器和上一稳定版本。外部写入或迁移不能靠配置回滚自动撤销。
超出权限或发布范围时先完成候选、测试和影响说明，再请求必要授权，不中断已获授权的实现。
