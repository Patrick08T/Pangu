# Pangu 行为追踪与节点调试审查

## 方法与范围

采用官方 [OpenCodeReview Delegation skill](https://github.com/alibaba/open-code-review/blob/main/skills/open-code-review-delegate/SKILL.md)。OCR CLI 生成文件清单与逐语言规则，由当前 agent 读取差异和调用上下文完成审查；没有配置或调用额外的审查模型端点，也不将 CLI 预览本身视作代码审查。

审查基线为任务开始时的工作区快照，保留用户原先的未提交改动。在 `.artifacts/trace-debug-review` 独立仓库中比较本轮变化，没有修改原工作区的 Git 暂存区。审查包括去除执行限制、显式预算、节点暂停/继续/单步、追踪采集/查询/导出、权限、清理和原生 Codex 补丁。

最终差异共 106 个文件：OCR 可审查的 61 个代码/配置文件全部覆盖，另人工审查 `native.patch`，合计审查 62 个，44 个按默认测试/文档过滤规则跳过。可审查文件覆盖率 100%，全部变化文件的代码审查覆盖率 58.49%；不把测试执行计为逐文件审查。逐文件处置见 `.artifacts/trace-ocr-coverage.json`，规则、清单分别见 `.artifacts/trace-ocr-rules.json`、`.artifacts/trace-ocr-preview.json`。

## 发现与修复

| 问题 | 严重程度 | 修复与验证 |
| --- | --- | --- |
| 工具结果中的裸密钥、私钥和 JSON 字符串内嵌凭据可能进入 trace | 高 | 在共享诊断脱敏入口补齐常见密钥、JWT、完整/截断 PEM 私钥和转义 JSON 凭据；先验证测试失败，再验证脱敏成功。 |
| trace 写入失败被当作普通执行错误重试，或被原生进程停止产生的取消信号掩盖 | 中 | 写入失败分类为不可重试的 `trace`；原生执行器仍先停止进程，并保留停止未确认错误。测试确认存储错误可追溯、不会重试或误报为用户取消。 |
| 公开搜索会话拒绝本机工具时，在创建工具 span 前退出 | 中 | 拒绝分支先记录参数及失败回执，再以权限错误终止。真实 CLI 测试先证明缺失该事件；最终修复版构建及回归均通过。 |

同时修正了仍宣称整次运行只有六小时的审批界面和旧使用说明。长命令测试按原生异步会话的实际协议调用 `write_stdin`，确认命令真正完成，而非把首次返回视作命令结束。

## 验证与边界

本轮发现的三项问题均已修复并通过对应回归，未发现未处理的阻塞问题。最终验证结果记录于 [行为追踪与节点调试设计](行为追踪与节点调试设计-2026-10-28.md)，包括 Go 全量测试、98 个前端测试、真实 Hatchet 执行与崩溃恢复，以及最终原生补丁构建和本地 CLI 回归。

未调用外部收费模型，未部署或迁移正式产品库；不代表模型质量、长期负载容量或真实业务验收已通过。凭据脱敏基于当前环境秘密值及常见格式，不保证识别任意编码或拆分后的秘密。暂停发生在节点边界，正在执行的节点继续；暂停仍占用 Worker 槽位。默认无业务调用预算时，消耗与持续运行时间由任务、显式预算和主动取消控制。
