# Pangu 易用性调整

日期：2026-10-25。状态：用户已确认，已实现并部署到本机；自动测试与本机页面验收通过，新增真实模型验收仍受已确认的预算约束。

## 要解决的问题

项目成员希望描述任务并得到可阅读的结果。原入口同时暴露配置、版本、预检、JSON、节点和日志，让已配置项目的普通使用也依赖工程知识。此次目标是让现有能力可以直接使用，不以新增模块数量衡量完成度。

## 使用路径

选择项目 → 新建任务 → 选择助手 → 描述目标 → 开始执行 → 查看和下载结果。只有一个已发布助手时自动选中。用户每次运行固定当时选择的发布版本，草稿不会影响运行。

主导航保留新建任务、任务记录、助手、自动化。设置集中放置账号、项目、模板、编排、质量与审计。管理员完成一次账号与项目准备；操作者使用常用角色表单准备助手并发布，JSON 仅供高级编辑。

规划与设计只要求目标，背景可选。调研必须有授权来源，竞品分析必须有候选和比较维度；页面明确助手的能力范围。一次点击完成检查和提交，错误原地显示并保留输入。提交结果未知时冻结内容，以原请求键重试。

任务记录用标题识别任务。详情首先展示状态、待审批事项和产物；报告自动打开为纯文本，可下载。执行日志按需加载，原始定义、费用和评价折叠展示。失败、取消和过期继续保留真实状态。

## 验收与边界

- 已配置项目无需选择版本、手写 JSON 或单独预检，即可提交规划任务；一个目标字段足够。
- 无可用助手时提供准备入口；预检失败不创建运行；权限不足不能提交；连续点击和未知提交重试不能重复创建任务。
- 普通 JSON Schema 必填语义、当前项目权限、不可变版本和授权来源边界保持有效。
- 成功任务默认展示报告；审批始终可见；过期输入、标题和产物不再展示；日志收起时不请求其分页数据。
- 保留现有高级能力与已有链接，不删除业务数据，不增加引擎、供应商、聊天后端或搜索费用。

成功指标是上述场景能够完成，随后由真实用户确认是否更容易使用。暂不声称提高了采纳率或完成率；没有编造基线、改善百分比与上线日期。

任务拆分、问题证据和竞品参考见 [产品可用性审查](产品可用性审查-2026-10-25.md)。采用 TDD，已通过前端 44 项测试、类型与构建检查、后端全量测试及数据库测试。原生 Codex 独立审查未发现新增中高风险。

本轮不启动新的真实模型验收，避免越过已确认的预算约定；本机页面使用现有成功运行核验结果展示。联网搜索仍依赖管理员提供搜索服务凭据，没有凭据时明确阻止相应任务。实际执行记录在审查文档中补充。
