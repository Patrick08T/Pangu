# 七个通用协作角色优化与验收

日期：2026-10-28。实验编号：ROLE-GENERAL-20261028。

执行依据：[build-optimize-workflow](C:/Users/pengtaotao/.codex/skills/build-optimize-workflow/SKILL.md)。目标是移除角色对特定项目、语言、框架及交付形式的预设，同时保留专业职责、授权和验收边界。

## 发现与修改假设

配置 v1 明确包含固定构建命令、特定语言性能工具、联调网关和项目版本管理约定。这些是可观察的适配限制；本轮没有跨项目真实运行样本，不能据此断言已经发生了某类模型执行失败。

修改假设：让角色先核对项目类型、阶段、技术栈或内容格式、授权资料、目标版本和验收标准，再选择适用方法，可以减少对错误技术栈和流程的强行套用。潜在回归是过度泛化导致检查不足、将缺证据解释为不适用、弱化权限或降低性能收益门槛；本轮的静态场景走查专门覆盖这些风险。

## 通用工作方式

1. 复用已提供的项目上下文，只补影响结果的缺口；无代码或无在线服务时采用适用的资料、数据、界面和流程证据。
2. 专业角色只承担本职工作；不要求每次任务都启用全部七个角色，也不由角色自行创建 Agent。
3. 保留来源、版本、事实、假设、反证、失败查询和未解决项；同一可靠快照可以复用，数据变化时重新读取原始来源。
4. 验收逐项标为通过、失败、未证明或不适用；缺环境、缺资料不是不适用。
5. 取消、预算不足、版本冲突或状态不明时停止新增动作并交付部分结果；恢复前核对实际状态，不能盲目重复有副作用的操作。

只读角色仍为验收、安全和运维；其他四个角色保留原本的工作区写入能力。QA 只改测试、产品经理只在授权范围内落盘文档/配置等限制由职责提示约束，不能当作文件类型级的强制隔离。真实权限与预算仍由执行器控制。
