# 人工审批持久等待

## 行为

人工审批不再设置过期时间。工作流到达带 `approval: {}` 的节点时，运行状态为 `waiting_approval`（待审批），暂停后续节点派发。等待期间不启动模型进程；批准后由持久事件恢复执行，驳回或撤回则结束。用户仍可取消整个运行。

Worker 重启后恢复同一个审批，不重复请求人工确认。开始执行前仍核验批准人权限、冻结输入、完整报告摘要和 Git 检查点；等待时间不会放宽这些条件。独立的手动调试暂停仍需按原规则恢复。

运行列表可筛选“待审批”，详情明确显示暂停原因与批准后的行为。角色配置、流程编辑器和对话式工厂不再提供或生成审批期限；新的 API 请求不接受 `approval.timeout_seconds`。

## 修改范围

- 工作流审批配置改为空对象，删除期限参数和一小时上限。
- 调度器只等待审批事件，删除审批超时计时器；运行状态从当前审批记录实时读取。
- 审批事件不再按期限过滤，保留批准/驳回/撤回、幂等消费和执行前重新授权。
- 数据迁移 `0045_approval_wait.sql` 固化旧审批的过期历史后删除期限列；已有报告、批准主体和内容摘要不变。
- 更新 API、生成的前端类型、配置编辑器、运行列表/详情、交付构建和对话式工厂。

历史失败运行不会自动变回待审批；本次修复没有增加异构节点检查点恢复能力。运行 `733b1cd1-704a-4c67-964b-c12ecf109d04` 仍保留原失败状态，其过期审批及完整计划保持可查。
