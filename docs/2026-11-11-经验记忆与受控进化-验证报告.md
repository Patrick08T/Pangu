# 经验记忆与受控进化：工程实现与验证记录

日期：2026-11-11。依据：[已批准设计](<superpowers/specs/2026-11-09-跨任务经验记忆与自动进化-design.md>)、[实施计划](<superpowers/plans/2026-11-11-跨任务经验记忆与自动进化-implementation.md>)。

## 交付边界

经验持久化、授权来源、冻结选择、执行输入、成果依赖、审批代际、实验评测、发布/观察/回退及 API/UI 的工程链路已实现。自动能力默认关闭；本轮未启用生产学习、执行生产迁移、发布配置或切换生产入口，未暂存、提交、推送或主动上传源码。

**这不是“真实自动进化已验收”的声明。** 设计第二阶段的真实模型无经验/有经验配对收益尚未验证，因此第三阶段的真实自动采用不得据此启用。真实 Hatchet 对账/恢复、进程重启与物理隔离边界也未完成实测。工程回归与审查已收尾；全仓 Go 单次命令仍受 Windows webhook 测试程序访问拒绝影响，不能标成整条命令通过。

## 已实现的关键闭环

- 经验有效状态与投放状态独立；来源、授权、保留期、检查器及收益证据分别验证。shadow/paused 不参与新任务冻结，但缺失记录和既有引用失效仍拒绝复用。
- 接收请求时冻结经验水位与投放修订；参数绑定后选择。同一逻辑输入恢复固定上下文，最多四条、每条 2 KiB、合计 8 KiB；读取失败不冒充空结果。
- 执行、成果恢复、检查点、fork、审批继承和后继重建检查可传递依赖。审批继承要求父子各自的持久化证明与原批准输入严格一致。
- 候选仅允许 Instruction 变化；实验、套件、检查器、保留集预算和统计规则由服务端控制。私有正文可擦除，版本身份与审计元数据保持不可变。
- adopted 与 stable 分离；观察期间保持目标占用，旧代际回执和人工后续修改不能被覆盖。发布后原来源失效仍阻止采用和稳定，回退不依赖已失效来源。
- 稳定晋级必须覆盖全部可能的候选业务请求。失败、未完成、缺失执行证明或部分快照的请求不能消失在分母中；覆盖不足保留原截止时间并在到期后回退。
- 启动 API 只返回持久化意图，202 不等于评测完成；现有调度维护循环负责继续推进。界面权限服从当前服务端授权，未知提交结果保留原幂等键。
- 派生正文清理要求正式清理因果、完整血缘、全闭包停止证明及受管本地目录。清理受分页、公平游标和单项时限约束；nil 返回不等于整个命名空间已清空。

## 审阅与工作区保护

原始报告、历史发现、明确跳过项及后续修复记录均保留。当前源码审阅结合 OCR 原生可执行文件的 preview/rules 与实际逐文件读取，不以 preview、测试通过或事后采样哈希代替语义审阅。测试文件多数被 OCR 默认过滤；没有宣称整个仓库或全部测试逐文件审阅。

[最终覆盖账本](<../.artifacts/experience-implementation-20261111/review-final-ledger.json>)按 `(path,status)` 及审阅时哈希核验：460 个可审身份 = 309 个当前内容匹配实际审阅 + 151 个任务前内容未变的明确跳过；缺项 0。变更范围 309/309 覆盖，整体实际审阅比例 67.17%，不是整个仓库 100% 审阅。另有 OCR 排除 512 项（465 项默认测试路径、47 项不支持扩展名），其中仅 23 项有匹配的手工审阅哈希，不夸大为全部测试已审。

证据保留于[发现处置记录](<../.artifacts/experience-implementation-20261111/review-dispositions.md>)、[审批当前证明](<../.artifacts/experience-implementation-20261111/review-approval.json>)、[memory/evaluation 当前审阅](<../.artifacts/experience-implementation-20261111/review-memory-current.json>)、[擦除审阅](<../.artifacts/experience-implementation-20261111/review-erasure.json>)、[runtime 当前审阅](<../.artifacts/experience-implementation-20261111/review-runtime-current.json>)及[Lead 修复审阅](<../.artifacts/experience-implementation-20261111/review-repairs-lead.json>)。原报告、原始 draft 和实际审阅时间保持不变；汇总脚本不代替语义审阅，也不补造历史哈希。

最终 `git diff --check` 通过；独立 PostgreSQL 仅对本轮数据目录执行正常 fast shutdown，后台任务退出 0，数据目录保留，无删除或业务数据库操作。Git 原生 patch 输出与原暂存区基线 SHA256 均为 `C721A9FF7E1CFFE91BB24C13C1645D79956C4434FECB6632E4929F37E431D510`，证明当时原暂存区逐字节保持。首次通过 PowerShell 捕获输出作文本比较报告不等，改用 Git 原生文件输出后确认是比较方式问题，未操作暂存区。

审阅工具曾经由 npm 包装器启动，触碰本机 OCR 的 last-update-check；无实际安装/源码上传证据，但不能据此断言未发生注册表更新检查。后续一律使用已安装原生可执行文件，不修改或抹除这项记录。
