## 修复清单

1. 调研、竞品分析缺少来源时，在表单和服务端校验阶段拒绝，避免浪费模型调用。提供“用竞品名称搜索官方资料”按钮，由用户明确选择公开发送内容。
2. Eino 只收到本次授权可用的工具；不再让模型试探不存在的搜索词或文件索引。
3. 报告必需章节必须有内容；调研/竞品必须有非用户输入的事实证据；授权了网页、文件时必须分别有相应实际读取的事实依据。
4. `register_report` 参数或结构错误回传模型，在剩余预算内修正；成功登记或工具预算用尽后不再额外调用模型。
5. 成功登记后，同批余下工具直接跳过，不访问外部服务、不消耗预算，也不因第二个登记触发预算错误而丢失首份有效报告。
6. Codex 模型 ID 在预检时拒绝无效值；400/401/403/404/422 分类为不可重试错误，429 保留限流重试语义。错误状态与脱敏展示文本分离，长 JSON 不影响分类。
7. Eino→Codex 内部报告参数允许最大 1 MiB；普通节点摘要仍受 16 KiB 限制。超限明确失败，不静默截断。
8. 任务详情增加交付检查；仅执行成功不再暗示结果通过验收。证据检查也不声称已证明引文与结论的语义关系。

## 真实账号验收方案（待确认预算）

复测同一个“Pangu 与 Eino、Coze 对比并提出规划”任务，先连续运行 3 次；如有问题，修复后再连续运行 3 次。总上限 6 条任务、60 个 Codex 会话、12 次原生搜索，关闭节点重试。只读取本项目已提交的 `README.md` 与公开官网资料，不修改源项目。

每条任务硬限制：最多 10 个 Codex 会话、2 次搜索、8 次 Eino 工具调用、0 次节点重试；固定输入、模型连接和项目 Git 基准。所有失败均保留，不只选成功样例。

验收要求：

- 实际发生原生联网搜索；至少读取 Eino 和 Coze 的官方资料及 Pangu 的授权项目资料。
- 输出覆盖受众、能力、使用门槛和产品边界；区分框架与产品，不凭空排名或编造实测指标。
- 关键事实可回溯到实际读取的原文；逐条人工核对引用是否支持结论。
- 提出有证据关联的改进优先级、范围和可执行验收条件，不能只给空框架。
- 产物可下载，工具证据和用量可追踪，无文件越权、未授权外部发送或预算越界。
- 当前版本连续 3 次全部达到要求才算该代表任务通过；任何一次失败均不能报告重复验收通过。

## 明确限制

本轮未扩展长期记忆、任意 MCP、自动发送私有搜索词或读取未提交项目内容。规则校验只证明来源被读取、引文存在及结构达标，无法自动证明所有结论正确。3 次代表任务通过也不等于所有业务场景长期稳定；当前真实重复结果尚缺。
