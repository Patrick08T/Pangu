# 工厂助手模型选择：实现与验证

## 问题与修改

原页面的“生成方案使用的模型”实际只选择模型连接。环境仅有一个使用 Worker 默认模型的 Codex 账号连接，因此无法选择具体模型、推理强度和 Fast。

现在在工厂对话的“继续对话”区域提供模型连接、Codex 模型、推理强度和 Fast 三态选择。复用 Worker 当前模型目录及能力校验，配置不另建缓存。普通 API 连接继续使用发布时绑定的模型。

每条消息保存 `model`、`reasoning_effort`、`fast`，生成工作流保存相应运行快照。`fast` 省略表示继承，`false` 明确关闭，`true` 明确开启。默认模型下不接受独立强度和 Fast；切换模型或连接时清除旧参数。

历史对话展示当时提交的参数，并将最新一条消息的参数作为继续对话的初始值。用户当前编辑不会被定时刷新覆盖。默认参数标注为继承，不将当前 Worker 默认值冒充历史实际解析值。

断网重试复用原请求 ID 和参数。Fast 按布尔值比较，避免 JSON 重新解码后的指针地址不同导致错误冲突。相同 ID 的参数变化返回冲突。工厂模型选择仅用于生成方案，候选 Agent 独立配置；生成器仍通过受控 Eino→Codex 桥接，不增加项目文件修改权限。
