# 优化功能使用

> 2026-10-28 归属模型更新：角色、工作流和模型连接在工作空间共享，运行时选择项目；模型连接无需项目授权登记。本文旧的模板绑定/项目连接设计仅保留为历史背景，当前以 [共享角色与工作流](../specs/共享角色与工作流.md) 为准。


本轮沿用 Hatchet + Eino + 原生 Codex、独立产品 PostgreSQL 和中文控制台。以下功能需先完成原有项目、身份与 Worker 配置；凭据缺失不会被模拟数据掩盖。

## 首次运行与版本

进入“首次运行”，按环境、项目、连接、模板、运行的顺序准备。连接使用表单及授权密钥引用，项目 Agent/工作流使用已发布版本选择器。输入从已声明的参数结构生成；产品经理仍明确填写任务与资料授权。高级 JSON 保留用于复杂编排。

预检查不会调用收费模型。输入或版本变化后必须重新检查；提交结果未知时输入冻结、原请求键保持不变，通过回执查询或重试确认。配置与权限始终从原始来源读取。

## 人工采纳、评测与证据

运行详情的“人工采纳评价”支持采纳、需要修改、拒绝及理由，绑定当前定义、输出和文件摘要，保存负责人及修订。只允许飞书会话；API Token 不能代填人工验收。来源不明的历史评价需重新评定，不计入人工采纳。运行成功与业务采纳分开显示，关联重跑/返工按业务任务去重。

“质量与评测”可保存固定输入、预期结果和验收规则，显式勾选同意保留后建立用例，再选择不同发布版本运行比较。保留原始逐次结果，不能由模型自动宣布真人采纳。用例正文保留30天、元数据90天，删除用例会删除其关联，不延长原运行产物保留期。

产品经理报告增加 `claims`：结论、事实/推断/未知、具体来源原文、资料日期和适用范围。原文必须来自实际已读资料；日期未知及资料冲突明确保留。原文匹配只证明读取过，不证明结论成立。运行详情可逐条核验为支持、部分支持、不支持、过时，记录理由和修订。

结论人工核验同样只允许飞书会话，写入前重新检查权限并记录来源；旧来源未知的判定只作历史信息，需重新核验。

## 审核与方案到交付

节点或工作流绑定可配置 `approval: {"timeout_seconds": 3600}`。审批绑定节点定义、输入、直接上游输出与当前 Git 头；内容变化使旧批准无效。运行所有者或项目管理者通过飞书会话批准/驳回，批准尚未消费时可以撤销。等待使用 Hatchet 持久事件，Worker 重启不丢决定；过期、撤权和旧摘要不能放行。审批等待独立计时，但仍计入整次运行6小时上限。

审批与 Codex 检查点变更不能混在同一并行层；通过 `depends_on` 排为独立步骤。只读 Codex 也会生成检查点，因此同样受此约束。

在成功的方案设计报告中选择任务，同时选全依赖；选择同项目、固定发布版本的可写 Codex 实施 Agent 和只读审查 Agent。项目必须登记真实验证命令。系统生成不可变交付草案，保存范围、依赖、交付物与验收条件；选中任务作为一组交给实施节点，随后执行独立审查节点。

确认草案后发起运行，批准实施范围后才执行。专用交付 ZIP 要求两个节点均有成功的项目验证证据、运行确认停止，并有针对当前产物的人工采纳。普通运行产物可提前下载检查，不表示已完成验收。默认仅交付差异/ZIP，不创建 GitHub PR、不 push、不合并、不发消息。

## 用量与预算

在工作流高级配置中指定整次运行额度，例如：

```json
{"budget":{"model_calls":20,"search_calls":10,"codex_sessions":3}}
```

每类0–4096，0表示不允许该类新增调用。未配置预算时默认分别为1056、960、96；显式设置预算应填写三个字段，遗漏字段按0处理。重试计入累计，外部请求发出前通过事务原子预留，失败或结果未知不退还；预算耗尽阻止后续调用，已发出的请求仍可能收费。

当前硬预算是调用次数，不是货币封顶。Eino统计实际模型 HTTP 请求、搜索统计请求，Codex统计原生会话；Codex 会话内模型调用由原生工具次数和超时约束，不在此层逐次限额。

Eino token 取自提供方响应，Codex token 取自 CLI 报告；缺失或 Codex 默认全零显示未知。连接可登记 `price` 的 USD/CNY 单价：`input_per_million_micros`、`output_per_million_micros` 均为每百万 token 的微货币单位，1000000微单位等于1货币单位。金额只作估算，未计缓存折扣、阶梯、税费；没有 usage 或单价不显示零账单，Codex订阅不折算单次金额。

详情展示节点排队、执行、调用和人工等待；并行耗时不能相加当总时长，复用或跳过节点没有新增执行。

## GitHub Issue 事件入口

本轮选定一条入口：指定仓库的 Issue 被加上指定标签。维护者先配置至少32字节的 `PANGU_HOOK_SECRET_*` 服务端密钥，项目管理者在“GitHub 任务入口”选择固定发布版本、仓库、标签和密钥引用，并明确勾选启用。配置不可变，变更时停用旧入口并新建。

GitHub Webhook 配置 JSON、Issues 事件与同一 Secret，接收地址为控制台给出的 `/api/hooks/github/{id}`。本地回环地址不能被 GitHub 直接调用，需要维护者提供可达 HTTPS 反向代理。登录飞书不授予任何飞书消息权限。

接收端验证原始正文的 HMAC-SHA256、事件ID、仓库、标签和载荷边界；事件只映射到已有项目、固定版本和持久提交。同一事件ID改正文返回冲突，相同正文不同事件ID关联原回执。撤权或停用后不接受新提交，已接受意图继续处理。

版本输入为 `repository`、`issue_number`、`issue_title`、`issue_body`、`issue_url` 的 JSON。版本需接受此结构；它不自动转换为产品经理 brief，也不授予正文中URL的访问权限。可写 Codex 节点必须包含人工审批。默认不向 GitHub 发送任何内容。

## 受限分支与检查点返工

运行详情可预览各节点实际可确定的结构化参数，并定位错误节点；上游未就绪时显示等待。API `/workflows/preview` 可在执行前对完整 JSON 定义做相同检查，不调用模型。

条件例子（节点的 `when` 字段）：

```json
{"field":{"from":"$input","pointer":"/enabled","type":"boolean"},"equals":true}
```

工作流需声明对应 `input_schema`。字段还可来自直接上游的结构化输出；只允许布尔/字符串精确匹配，无脚本和循环。未命中不派发节点，其依赖节点也跳过；首版没有互斥分支自动合并。

运行停止后，在“检查点返工”选择成功 Codex 节点，编辑新定义，预览复用与重做范围并确认。只复用串行无条件 Codex 成功前缀；修改某节点后，该节点及后续失效；全局输入改变时全部重做。并行文件检查点合并、报告复用不在本轮范围。发布版本不可原地改写，调整版本节点须使用新发布版本或明确的新定义。

新运行记录父运行、检查点和独立历史。再次返工可复用导入检查点；整次重新运行始终回最初Git基准并执行全部节点。文件恢复不撤销模型调用或远端工具副作用。相同键/输入/发起人找回原回执，即使来源历史已清理；新建返工仍要求来源检查点在保留期内。

## 验证与外部验收

迁移顺序为0025–0036（后续以仓库迁移清单为准），先备份，再显式迁移、重启API和Worker。构建/验证命令见README。功能状态和本轮证据以[优化实施进度](优化实施进度.md)为准。

真实飞书登录、真实模型/Brave、真人采纳和干净Windows安装尚需[试点验收](试点验收.md)。模拟模型或执行器测试只验证系统行为，不证明报告质量、真实费用或团队采纳率。
