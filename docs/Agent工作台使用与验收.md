# Agent 工作台使用与验收

日期：2026-10-26。范围：团队、企业私有部署；AW01—AW08 已实现并部署到本机 `http://127.0.0.1:8081`。对应[设计与任务](Agent工作台设计-2026-10-26.md)。本文件区分功能验证与生产试点，不以账号冒烟代替任务质量验收。

## 从哪里进入

打开“助手”，点击助手名称，即进入独立 Agent 工作台。现有“产品经理 · Codex”入口为 `#/catalog/b237c0da-0c7c-4788-92a6-1a6ab0b08ddc`。工作台编辑单个助手，工作流画布负责多个助手的连线和顺序。

1. 在“职责与说明”填写名称、用途和职责。套用预设会先确认替换范围。
2. 在“模型与执行”选择 Eino 产品经理、Eino 通用助手或原生 Codex。Eino 选择已发布共享连接；原生 Codex 使用 Worker 专用账号，通过“Codex 模型”下拉框选择型号，或选择“Worker 默认模型”。“刷新模型列表”重新读取 Worker 当前程序自带目录，不调用模型。目录未包含已保存型号或读取失败时保留原值。
3. 在“工具与资料”查看真实能力，在“执行限制”设置超时、重试、工具次数、文件权限及审批，在“输出格式”配置文本或结构化字段。“交接契约”中的交接目标、输入与上下文、交付物、验收标准、异常处理为发布和运行必填，详见[交接契约说明](Agent交接契约.md)。
4. 保存草稿。未保存的修改会阻止试运行和发布；离开有提示。修订冲突会保留本地输入，可查看服务器草稿后决定是否重新读取。
5. 右侧填写任务目标，“检查环境”不调用模型；“试运行草稿”才创建真实任务。同页查看回执、状态、输出、错误、尝试、工具证据及用量；完整详情可查看产物。
6. 点击“发布”，核对当前修订的检查和试运行情况。未经成功试运行的修订需要主动确认后才能发布。发布生成固定版本，旧流程和定时计划继续使用原版本。
7. 在“版本”比较历史配置，点击“恢复此版本为新草稿”，再在页内确认。恢复只替换配置，保留当前名称与项目，生成新的草稿修订；不会改写历史版本。

窄屏使用“配置 / 试运行 / 版本”切换。每次运行是独立任务，不携带上一轮会话。没有逐字流式输出时，页面展示实际状态和完整结果。

## 失败和权限处理

- 网络提交结果未知：保留原输入、修订及请求键，使用“重试同一试运行”；不要另建请求猜测失败。刷新后从“草稿试运行历史”查回执。
- 409 修订冲突：本地修改不会覆盖服务器草稿；先比较，再决定保留本地副本或读取服务器内容。
- 请求键超过 89 天：拒绝重新派发；到期重试不能变成新的收费任务。正文保留 30 天，回执元信息保留 90 天。
- 查看者只能读。服务器逐请求检查项目权限，接受提交前还会在身份锁下重新检查运行权限；隐藏按钮不是权限边界。
- 模型费用没有账单实值时显示未知，Codex 订阅不换算单次金额。原生 CLI 会话内部请求不在本层逐次计数。
- 取消表示记录取消意图，实际停止状态和进程证据以运行详情为准。
