# 账号接入

Pangu 登录、模型调用和原生代码执行是三条独立链路。飞书负责成员身份；Eino 可以选择模型 API 或 Worker 专用 Codex 账号；原生 Codex 节点使用同一个专用账号。

## 飞书登录

按 [飞书与项目权限](飞书与项目权限.md) 配置应用、精确回调、租户及首位管理员。采用 v3 服务端 OAuth，通过 App Secret 交换授权码，不启用 PKCE、不回退 v2。保留浏览器绑定、一次性 state、五分钟过期、应用与回调地址校验。网页登录成功后，会话有效期为 12 小时。

本机已保存的 `.tools/feishu-secret.dpapi` 仅当前 Windows 用户可解密，`.tools/feishu-settings.json` 保存非密钥配置；两者均不进入 Git。`.tools/start-configured.ps1` 解密后仅为 Pangu 启动进程注入环境。重启入口：

```powershell
./scripts/stop.ps1
./.tools/start-configured.ps1
```

以上 `.tools` 文件属于本机配置，不随仓库分发，其他主机需独立配置。不得上传密文、应用 Secret 或 Codex 登录文件。

本机启动入口将 `PANGU_WORKSPACE_ROOT` 设置为 `%LOCALAPPDATA%/Pangu/workspaces`，与源码仓库隔离。项目来源不能包含 Worker 运行目录；不要在把 Pangu 本身登记为项目时沿用仓库内的 `.artifacts/workspaces`。

## 专用 Codex 登录

先按 [受控构建](../runtime/codex/README.md) 准备 CLI。管理员在 PowerShell 中启动登录，完成后恢复宿主环境：

```powershell
$previousCodexHome = $env:CODEX_HOME
try {
    $env:CODEX_HOME = (Resolve-Path './.tools/codex-home').Path
    & ./.tools/codex/codex.exe login
    & ./.tools/codex/codex.exe login status
} finally {
    $env:CODEX_HOME = $previousCodexHome
}
```

Worker 设置 `PANGU_CODEX_HOME` 和 `PANGU_CODEX_BINARY`，不使用宿主个人的 `CODEX_HOME`。`scripts/start.ps1` 默认使用上述 `.tools` 路径。账号过期时重新登录同一专用目录；不要把 Codex OAuth 令牌填入 API Key 或连接 JSON。

## Eino 共用 Codex

1. 在“项目与成员”登记项目，指定本机 Git 目录、分支与 Worker ID。
2. 在“模型连接”选择“Worker 的 Codex 账号”，模型可留空以使用 CLI 默认模型，然后发布固定版本。
3. 创建共享 Eino 产品经理角色，选择上述连接版本并发布；运行时选择项目。
4. 在“首次运行”填写任务、检查环境并提交。

连接 JSON：

```json
{
  "connection": {
    "provider": "codex",
    "model": ""
  }
}
```

Codex 连接不设置 `base_url`、`secret_ref` 或 `price`，不要求 `PANGU_CONNECTION_GRANTS`。它受共享配置管理权限、固定版本和归档控制；每次模型回复前从数据库重新读取连接。连接不选择其他人的账号，使用目标 Worker 的专用登录。管理员应仅向获准消耗该账号额度的成员开放项目执行权限。

Eino 继续管理产品经理工具、来源校验和报告登记。Codex 在独立临时空目录中以只读模式生成结构化回复；原生工具预算强制为零。工具请求返回 Eino 执行，不把真实项目路径交给桥接进程。原生 Codex 节点仍按自己的读写策略访问分配的运行工作区。

每轮模型回复占用一次 `codex_sessions` 预算，后续工具结果会随完整对话传入下一轮；不占用 `model_calls` 的 API 调用预算。记录 CLI 提供的 token 用量，费用保持未知。Eino 节点仍受三分钟总时限约束，桥接暂为完成后整段返回，不提供逐 token 展示。网络、账号额度和模型权限仍由 Codex 服务决定。

普通模型 API 连接可省略 `provider` 或使用 `openai`，仍须配置服务端凭据引用和项目授权。公开搜索复用 Worker 专用 Codex 登录和原生 `web.run`，无需 `PANGU_SEARCH_API_KEY`。产品经理每次 `search_public` 只把已授权的公开搜索词交给隔离的只读 Codex 会话；从工具结果登记来源，仍需 `read_web` 读取正文后才能作为事实依据。每次搜索同时占用一次搜索预算和一次 Codex 会话预算。普通模型生成桥接仍禁用原生工具。

## 验证

`scripts/check.ps1 -Database` 检查前后端、契约、架构、数据库、构建和静态分析。真实账号联调需显式设置 `PANGU_CODEX_BRIDGE_REAL=1` 并运行 `TestNativeCodexEinoProductManager`；该测试会消耗 Codex 额度，仅在独立测试数据库生成配置与内存报告。原生文件写入烟测为 `PANGU_CODEX_REAL=1` 下的 `TestNativeCodexWritesWorkspace`，仅写临时项目。
