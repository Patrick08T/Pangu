# Pangu 路线图与可执行任务

规划日期：2026-10-23。产品定位与成功标准见 [产品需求](PRD-Pangu.md)。下列29项保留产品验收标准，工程实现与证据见 [实施进度](实施进度.md)。M1–M3 的真实模型、登录和人工采纳验收尚未全部结束，不把代码完成等同里程碑关闭。具体边界见 [需求确认记录](需求确认记录.md)。

后续用户已授权搭建全栈基础，完成情况见 [架构设计](架构设计.md)。本表保留产品验收层级，工程执行改用 [46 项工程任务卡](工程任务卡.md)：共享模板绑定规则进入 C01–C04，产品经理能力拆为 C13–C16，飞书登录进入 U01，新增 U12/U13 管理页面。纯编排校验、HTTP 追踪、基础依赖检查和前端状态页已完成，不等于 M1-02、M1-03 或 M3 业务任务整体完成。

## 1. 已有基础与阶段成果

M0 已有 API/JSON DAG、Hatchet 节点独立调度与自动重试/恢复、Eino、原生 Codex、UTC Cron 和运行详情。现有测试及其局限见 [验证记录](验证记录.md)。本次只核对仓库，没有重新执行模型和服务测试。

| 阶段 | 要解决的问题 | 用户获得的结果 | 退出条件 | 依赖 |
| --- | --- | --- | --- | --- |
| M1：可控执行，下一阶段 | 任务跑过之后难查找、难终止，直接写项目难审查 | 能重复完成一个真实流程，知道哪里失败，能停止任务并检查修改 | PRD 前两项目标达标，M1-12 有证据；不依赖管理界面 | 现有 M0 |
| M2：可复用工厂，随后 | Agent/流程难复用，角色能力缺少证据 | 跨项目使用模板、固定项目绑定与版本，运行产品经理和研发流程 | 产品经理、修改验证、只读巡检三类模板通过；绑定不可迁移，新版本不影响历史和已有绑定 | M1 稳定；技术实证通过 |
| M3：小团队控制台，试点前 | API 门槛高，团队操作缺少权限和归属 | 可信同事能通过界面独立配置、运行、审查和追溯 | 试点成员独立走完任务；越权测试、审计和恢复演练通过 | M2；多人开放必须先通过 M3-01/05 |

阶段使用相对顺序，不指定发布日期。规模 S 表示一个较独立的行为，M 表示跨模块功能，L 表示涉及持久状态或故障语义；L 项需先通过设计关口，再按验收场景拆成实现提交。规模不是工期承诺。

M1-06/07 采用独立本地 clone，源文件/源 `.git`/分支保持原样；工作区只保护代码交付，不提供互不信任用户之间的读权限隔离。检查点与崩溃恢复仍须实证。M1-09/10 若 Hatchet 无法直接提供所需幂等和触发记录，需要设计最少持久元数据，不能用进程内缓存凑合。

### 首个迭代的取件顺序

1. **M1-01**：先锁定场景、验收样本和契约，避免在不同接口里定义不同状态。
2. **M1-02、M1-03**：建立校验、就绪诊断与事件，后续故障有证据可查。
3. **M1-04、M1-05**：让用户找得到、停得下运行；检查取消能力是否满足工作区恢复前提。
4. **M1-06**：先完成工作区生命周期设计与故障验证，再落实文件隔离；不能仅以创建目录成功结项。

这组工作完成后的可演示成果是“提交 → 列表/详情 → 定位失败 → 取消 → 源目录不受任务写入影响”。尚不代表 M1 已可发布；后续仍须完成失败尝试处理、产物、重新运行、Cron 和真实验收。

## 5. 后续候选，暂不排期

这些不是当前承诺的实现任务；出现对应使用证据后再拆分和估算。

| 候选能力 | 用户收益 | 进入开发的条件 |
| --- | --- | --- |
| 条件分支、有限循环、子流程 | 根据结果选择路径并复用复杂流程 | 真实模板无法用当前 DAG 清楚表达；先定义跳过、汇合、循环上限、取消和重放语义 |
| 依赖就绪即调度、多项目 Worker 路由 | 减少无关节点等待，让不同项目并行 | 排队/执行数据证明当前分层或单项目限制影响使用；先解决工作区归属和凭据边界 |
| 签名 Webhook 触发、结果通知、Git PR 交付 | 接入已有研发流程，减少人工搬运 | 有明确服务和调用方；定义事件去重、权限、重试、人工批准以及外发数据范围；默认不自动合并 |
| 拖拽编排、时区与更丰富定时策略 | 降低复杂流程和跨时区计划的配置成本 | 试点显示 JSON/UTC 是主要障碍；时区功能必须明确夏令时重复/缺失时间与补跑规则 |
| MCP/其他工具接入、评估数据集扩展 | 扩展 Agent 能力并比较不同配置的质量 | 有具体工具与任务需求；补齐信任、权限、调用预算和产物质量评价后逐项接入 |

知识库、插件市场、商业计费、互不信任租户及大规模高可用不进入近期范围。

## 6. 统一完成定义与任务执行规则
