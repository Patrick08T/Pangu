## 执行次序与客观证据

1. **真实登录和角色**：首位管理员登录并登记成员；验证不允许的租户/未登记身份被拒绝。三种角色分别尝试读取、运行、修改成员；查看者写入和跨项目访问应被拒绝。退出、撤销 Token、禁用后再请求应失败，禁用成员的未来计划暂停。
2. **产品经理四能力**：使用[模板与产品经理](模板与产品经理使用.md)和 `examples/product-brief.json`，执行调研、竞品分析、产品规划、方案设计；人工抽查来源能打开、日期对应、未证实内容标为未知、规划关联调研证据、方案任务依赖无环。分别记录报告 ID 和需要返工的原因。
3. **原生 Codex 小任务**：选择隔离分支上的真实小改动，先写文件/测试验收条件；在控制台启动写入模板，查看真实命令结果和产物 diff，由人决定采纳。只读模板单独验证没有产物写入，失败/取消不得发布失败尝试文件。
4. **计划与版本**：三类模板各验证手动运行和一次 UTC Cron；发布模板 v2 后，现有项目绑定与旧计划仍使用 v1，只有显式升级才改变。演练后暂停测试计划，避免持续消耗额度。
5. **干净安装及恢复**：按手册首次配置和登录，记录解压到首次成功运行耗时；在无活动运行时冷备份，恢复到独立目录和端口，检查配置版本、请求回执、历史尝试及保留产物。记录完整恢复耗时，不用单个查询耗时代替 RTO。
6. **三角色独立使用**：每位成员独立完成其有权执行的配置、运行/查看、失败定位和产物审查；记录求助次数、操作耗时、失败原因及后续优先级。
