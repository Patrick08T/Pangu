# 模型临时故障自动重试

## 本次故障

运行 `50acec3c-21b8-4b88-ae53-7333a0c8f0ee` 在人工纠偏后的第 2 轮 `execution_plan` 失败。提供方模型事件 `1441` 确认 `gpt-6.1-sol` 容量不足。前面的七个规划角色已完成本轮修订。旧实现将容量不足记为普通 `execution`；工作流的节点策略全部为 `retries: 0`，因此直接失败。根流程的重复报错是在读取同一个失败子节点，没有再次请求模型。

## 已确认的策略

- 临时模型容量不足、限流、HTTP 408/500/502/503/504，以及模型传输层确认的超时、连接中断等故障持续重试。
- 从每次失败的持久结束时间计算，依次等待 30 秒、1 分钟、2 分钟、4 分钟，之后每次 5 分钟。
- 模型恢复则继续，用户取消或已设调用预算耗尽则停止。没有配置预算时不增加隐式调用上限。不自动切换模型。
- 鉴权、模型不存在、参数、输出校验、工具权限、账户额度、用量记录、追踪写入和业务错误不进入模型持续重试。普通节点原有 0–2 次重试策略仍独立保留。

## 调度与数据边界

复用现有 Hatchet 持久调度和 `node_attempts`，不增加数据库表或迁移。首次同层节点仍并行派发；收齐结果后只将模型临时故障加入重试队列。永久失败直接终止该层。队列按持久失败时间排序，重试逐个派发；因此页面显示“下次重试不早于”，实际启动还取决于 Worker、调试暂停及先到期节点。

调度层使用 `SleepUntil` 持久等待。时间来源为数据库停止凭据；重放不能按当前时间重新计算派发顺序。重试使用包含原节点、人工修订轮次和模型重试序号的独立子任务标识。重启后重放既有调用，复用成功结果，只继续尚未完成的重试。调度和执行入口均保留取消、权限与调试校验。

模型错误只从实际提供方错误事件、结构化 API 状态和模型 HTTP 传输层识别，不从模型正文、工具输出或任意错误字符串推断。取消、未确认进程停止、追踪持久化失败和用量记录失败优先终止。

每次重试沿用同一个根运行，因此模型调用仍经过原有用量预留，失败或结果未知的请求不退回预算。Codex 重试使用新的隔离尝试目录，从最后成功检查点开始，失败尝试的未发布文件不会成为基线。研究节点重试可能重新进行该节点内的只读检索；此前成功的角色节点不重新执行。

人工纠偏原文、上一轮审核、已修订父报告和审核轮次原样传入失败节点的新尝试。规划恢复后仍创建下一轮待审批，持续重试不产生实施授权。

## 界面和接口

`NodeRun` 增加可选字段 `model_retry` 和 `next_retry_at`。后者仅在活动运行的最新失败节点处于模型等待时返回；取消、终止或日志过期时不返回。详情页展示等待说明、角色节点、修订轮次、模型重试次数及最早重试时间。流程图将其标记为“等待模型重试”，历史失败记录保留。

Hatchet 的 replay 可能保留旧 `ErrorMessage`。API 仅在当前状态为失败或取消时返回当前错误；活动运行及恢复成功后的旧诊断继续保存在尝试、事件和旧子运行历史中，避免“执行中”被误解成再次失败。
