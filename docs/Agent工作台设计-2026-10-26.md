# Agent 工作台设计与实施任务

日期：2026-10-26。状态：用户已确认，AW01—AW08 已实现；本地部署与验收记录见《Agent工作台使用与验收》。生产试点仍按独立清单验收。

## 目标与已确认边界

为团队、企业私有部署提供独立的单个 Agent 编辑工作台，让使用者在一个页面完成配置、试运行、定位错误和发布。入口为“助手”列表中的具体助手，工作流画布继续负责多个 Agent 的关系。

沿用 Go、Hatchet、Eino、原生 Codex、React 与飞书登录；项目绑定后不可移动，共享模板可以跨项目绑定。沿用已确认的 TDD、Git 管理和 Codex 原生 Agent 独立审查。

“达到商用标准”按下文证据验收。界面完成、模拟测试通过、一次模型成功，都不能单独证明生产可用。现有 `docs/试点验收.md` 中尚未完成的真实任务、恢复演练和多人使用记录继续保留。

## 当前差距

- `web/src/catalog/agent.tsx` 只提供角色预设、职责、连接、只读开关和输出字段；其他参数依赖 JSON。
- Agent 和连接等配置共用通用编辑页，没有同页调试、明确的修订状态、离开保护和版本差异。
- 运行要求先发布并跳到新建任务页；没有可追溯的 Agent 草稿试运行。
- 后端已有修订冲突检查、不可变发布版本、固定输入评测、幂等回执、运行尝试、产物、取消、审计和项目权限，可复用。
- Eino 产品经理使用固定工具集。原生 Codex 使用独立项目工作区；Eino→Codex 使用受限模型适配。两者的能力和授权边界不同。
- Codex 任务当前使用独立临时会话；Eino→Codex 当前返回完整回答，没有逐字输出。工作台不能把这些行为标成多轮记忆或流式生成。

## 竞品依据与方案选择

| 参考 | 已核实的做法 | 在 Pangu 中采用 |
| --- | --- | --- |
| [Coze 预览与调试](https://docs.coze.cn/guides_preview_debug) | 编辑时预览，查看请求的状态、输入输出和执行链路 | 配置区旁直接试运行；展示结果、实际执行尝试和工具记录 |
| [Coze 协同管理](https://docs.coze.cn/guides_collaborate_agent) | 历史版本可调试，也可恢复到草稿后重新发布 | 不覆盖历史版本；恢复形成新草稿 |
| [Dify Agent 入门](https://www.dify.ai/zh/blog/build-your-first-agent-in-dify) | 指令、模型、工具等分别配置，预览后发布，再查看日志 | 分区表单、草稿与发布分离、调试和运行追踪闭环 |
| [LangSmith 助手管理](https://docs.langchain.com/langsmith/configuration-cloud) | 配置模型、提示词及工具能力，按助手版本测试 | 固定版本测试，复用已有评测样本比较版本 |

这是针对 Pangu 的适配判断，不代表存在唯一的行业最佳产品。

比较三个实现方案：

1. **继续增强通用表单**：改动最少，但编辑、调试、版本仍然分散，不能解决本次主要问题。
2. **独立 Agent 工作台，复用现有底座（推荐）**：新增专用交互和草稿试运行接口，继续使用现有调度、隔离、回执及权限，迁移面可控。
3. **引入完整 Coze/Dify 平台**：需要整合第二套资源、权限、版本及执行体系；现有 Hatchet/Codex 语义不能直接替换。本轮不采用。

## 页面与操作

保留现有 `#/agent` 列表和 `#/catalog/{id}` 链接。配置类型为 Agent 时进入专用工作台，已有链接仍能到达同一资源。

桌面布局：顶部为助手名称、所在项目、当前修订、保存状态和“保存草稿 / 发布”；左侧为配置分区导航，中间编辑，右侧为试运行。窄屏按“配置 / 试运行 / 版本”切换，不横向挤压表单。

### 配置区

| 分区 | 本轮功能 |
| --- | --- |
| 基本信息与职责 | 名称、用途说明、职责提示词；中文角色预设；切换预设前展示替换范围并确认，避免覆盖已写内容 |
| 执行方式与模型 | 明确区分“Eino 产品经理”“Eino 通用助手”“原生 Codex”；产品经理可选调研、竞品、规划、方案设计；模型连接用名称与固定版本选择 |
| 工具与资料范围 | 展示真实运行能力、条件和授权方式。产品经理显示搜索、网页、项目资料、报告登记等现有工具；可用资料通过试运行输入逐项授权 |
| 执行限制 | 超时、重试、工具调用上限、Codex 只读/项目内读写；数值上限和默认值来自当前运行契约，前后端均校验 |
| 输出格式 | 文本或结构化对象；复用字段编辑器配置输出字段和必填项；缺失或无效字段阻止相应操作 |

通用 Eino 不显示产品经理专用工具。Eino→Codex 不显示原生 Codex 文件写入权限。原生 Codex 不显示 Eino 连接字段。切换执行方式时明确哪些字段会清除，保留通用职责和说明，不静默携带无效配置。

隐藏运行端不支持的温度等参数；不提供没有实际执行能力的 MCP、技能或知识库开关。现有高级配置中的审批要求等字段必须保留、可识别；工作台不静默删改已有权限限制。

连接列表只返回显示所需的安全信息。操作者不读取管理者专用的端点和凭据配置；只读成员不请求无权访问的连接选择接口。凭据只在服务端管理。

### 保存与冲突

采用显式保存，页面显示“未保存 / 保存中 / 已保存 rN / 保存失败”。不引入浏览器持久化配置缓存。

- 刷新、离开页面、切换项目或助手时，对未保存内容使用现有离开保护。
- 保存附带服务器修订号；409 时保留本地内容，展示服务器版本与本地差异。
- 用户可以复制本地内容，或明确丢弃并重新读取；不提供无条件覆盖服务器的快捷按钮。
- 试运行和发布只使用已保存修订。存在本地未保存修改时要求先保存，避免测试的内容和屏幕内容不一致。
- 保存、发布和归档期间锁定相关操作；会话失效后不得自动重发写请求。

### 同页试运行

试运行是单次任务；每次输入独立执行。页面明确标识试运行对象为“草稿 rN”或“发布版本 vN”。

1. 填写任务目标；产品经理使用已有资料与目标表单。
2. “检查环境”只做输入、连接和 Worker 检查，不调用收费模型。
3. 点击“试运行”才真正提交；默认只运行一次，失败重试受该 Agent 策略限制。
4. 同页显示回执、排队/执行/取消中/完成状态、结果和错误；提供取消与完整运行详情入口。
5. 展示可观测的工具记录、执行尝试、产物与实际用量；未知费用显示“未计量”，不显示零费用或伪造逐字输出。
6. 提交结果不明时保留请求键和输入，通过同一幂等键查询或重试，不创建第二次任务。
7. 已开始的任务固定使用接受时快照。之后修改草稿，不改变在途任务；调试结果保留原修订标识。
8. 刷新后可从服务端读取该 Agent 的试运行历史和回执；保留期限到达后显示正文已清除。

试运行使用现有 Hatchet、Worker、项目隔离工作区、审计和数据保留规则。浏览器不能传入任意本机路径，也不直接执行 Codex。

### 版本、发布与评测

- 历史版本展示发布时间、来源修订、执行方式和主要配置，不再默认显示整段 JSON。
- 对比选定历史版本与当前草稿，逐项显示职责、模型连接、能力、限制和输出字段的变化。
- 恢复历史版本只创建当前对象的新草稿；仍受修订锁、项目和引用校验。恢复前确认会替换的内容。
- 发布面板展示静态检查、当前修订的环境诊断及试运行状态；旧修订的成功不能标记为当前修订通过。
- 发布始终由服务端重新检查配置和引用；没有成功试运行时明确提示，并由用户主动选择“发布未经试运行的版本”。不自动调用模型来满足发布条件，也不把成功回答等同于质量合格。
- 发布后可直接开始任务、进入评测或回到工作流选择固定 Agent 版本。已存在的工作流和 Cron 继续使用原固定版本。
- 复用固定评测样本与人工验收标准比较发布版本；本轮增加顺畅入口，不另建评测引擎。

## 服务端设计

### 草稿试运行契约

新增 Agent 专用的草稿诊断、试运行提交和历史查询接口，置于现有 catalog API 下。请求至少包含期望修订和输入；提交必须带幂等键。

- 服务端读取原始草稿，验证类型为 Agent、项目权限、未归档、期望修订匹配、配置有效和引用可用。不能依赖客户端传入的完整 Agent 定义证明测试来源。
- 成功接受时保存不可变执行快照，并将试运行记录关联到对象 ID、修订、请求 ID、操作者和时间。复用已有提交快照，不再保存另一份独立运行结果。
- 同一操作者、项目、幂等键、对象、修订和输入重试返回同一回执；内容或操作者不同返回冲突。
- 草稿试运行键使用 `Unix 毫秒时间戳.UUID`，安全重试窗口为 89 天，早于 90 天元数据清理；到期返回 409。即使旧记录已删除，旧键也不会重新创建模型任务。时钟超前超过 5 分钟时拒绝提交并提示校准。
- 首次提交已成功后，即使草稿已经更新或归档，重试只返回已有回执，不重新编译或派发。仍需检查当前项目访问权限；超过安全重试窗口拒绝重新派发。
- 试运行关联和提交回执必须原子落库，避免创建收费任务却丢失其来源记录。
- 后续派发、重启恢复使用已保存的快照，不重新加载最新草稿替换执行内容。
- 草稿来源标记仅供诊断和追溯，不能伪造正式版本，也不能成为工作流或 Cron 的发布引用。
- 历史查询按项目授权、分页并限制结果；正文沿用现有保留期限，元信息不能泄漏其他项目资源。

复用现有业务层校验和提交派发路径。接口契约、前端生成类型、权限路由和审计映射与实现同步更新。

### 权限与审计

沿用飞书项目角色：管理者和操作者可编辑、发布及试运行；查看者只能读取有权查看的配置、版本及运行。连接管理仍由管理者负责。前端隐藏按钮只用于交互，后端重新鉴权。

保存、发布、归档、试运行和取消进入现有审计。请求错误提供中文原因、可执行的下一步和请求编号；不回传环境变量、令牌、模型凭据或无界日志。

### 影响范围

| 层 | 需要到达的调用方与文件 |
| --- | --- |
| 入口与页面 | `web/src/catalog/{list,create,version}.tsx`，新增 `web/src/agent/` 工作台，按需调整路由和样式 |
| 前端复用 | `api/hooks`、`api/request`、`flow/history`、`flow/shape`、`onboarding/input`、`onboarding/catalog`、`runs/submission`、`runs/debug`、评测页面 |
| 服务端 | `internal/api/catalog*`、`internal/catalog` 草稿编译、`internal/submission` 幂等快照与关联、现有调度提交及查询路径 |
| 数据与契约 | 必要的试运行关联迁移、`api/openapi.yaml`、生成类型、契约测试、权限及审计映射 |
| 验证与文档 | 前端交互测试、数据库/API 测试、恢复和权限回归、中文使用说明与验收证据 |

不替换工作流画布，不另建调度器或模型网关，不迁移已有发布版本，不顺带重构无关模块。前端复用逻辑只在确有需要时提取，保持小函数和现有结构。

## 可独立执行的任务

按先测试后实现推进；依赖顺序用于减少并发修改同一模块，不要求每项新建独立框架。

| 编号 | 任务与交付 | 依赖 | 可判断的验收条件 |
| --- | --- | --- | --- |
| AW01 | 草稿试运行契约、服务端快照及来源关联 | 设计确认 | 修订冲突、跨项目、查看者、归档和非法连接均被拒绝；接受后的配置不可变；关联和回执原子保存 |
| AW02 | 幂等重试、诊断与试运行历史 | AW01 | 超时重试无重复派发；草稿变化后仍返回旧回执；安全窗口到期不重发；诊断不调用模型；分页与权限正确 |
| AW03 | 独立工作台入口、配置分区与能力匹配 | 设计确认 | 现有 Agent 链接进入工作台；创建后直接编辑；三类执行方式的可用字段正确；不丢失现有配置限制 |
| AW04 | 保存状态、校验、离开保护与冲突处理 | AW03 | 网络失败保留输入；409 不覆盖；切换项目或刷新有保护；无配置持久化缓存；查看者无写操作 |
| AW05 | 同页真实试运行与错误定位 | AW02、AW04 | 固定已保存修订；同页回执与结果；取消可用；实际尝试和工具记录可查；配置变更后旧结果仍标原修订 |
| AW06 | 版本差异、恢复草稿与发布面板 | AW04、AW05 | 恢复不改历史；并发恢复触发冲突；未保存修改不能发布；旧修订测试不冒充当前通过；旧流程和 Cron 引用不变 |
| AW07 | 评测入口、响应式与无障碍 | AW05、AW06 | 从工作台进入固定样本比较；键盘可访问核心操作；焦点、标签、错误关联完整；窄屏可编辑和调试 |

## 发布验收

本轮技术验收必须覆盖：

1. 现有助手和新助手均可打开工作台，三种执行方式可配置并保存。
2. 真实鉴权的跨项目与查看者测试；接口不会因隐藏按钮失效而越权，也不泄漏连接凭据。
3. 保存失败、并发编辑、页面切换和登录过期不静默覆盖草稿。
4. 草稿试运行固定来源修订；接受后修改草稿、服务重启和同键重试不改变快照、不重复派发。
5. 取消、失败、工具记录、输出字段不匹配等状态可定位，并提供明确后续操作。
6. 历史恢复形成新草稿；发布不改变旧运行、旧工作流和旧计划。
7. 浏览器验证关键操作、只读角色及窄屏；测试和构建结果记录到实施文档。

商用验收还需要经授权的真实 Eino→Codex 和原生 Codex 任务、失败恢复演练，以及现有试点验收要求。模拟测试和环境检查不代替这些证据；正式部署仍需按部署手册完成 HTTPS、访问边界、备份恢复和容量验证。未完成的项目明确记录，不宣称已经验证。

本轮开发默认使用已有记录和测试替身验证，避免隐式消耗模型额度。真实任务联调需按既有约定明确任务和预算；不会自动启用周期任务。

## 本轮不纳入

公网多租户与计费、任意 MCP/插件市场、通用知识库、跨轮长期记忆、语音、多渠道发布、AI 自动改写职责、多人实时共同编辑。不显示这些功能的空开关。若后续需要，应分别实现运行契约、权限与验收后再开放。

## 设计复核

已核对草稿、发布版本、试运行快照三者的语义，以及恢复、权限和配置读取边界。发布不强制调用模型，质量结论仍需验收证据。现有代码没有逐字流式输出或持续会话，本设计未将其列为可交付行为。

整体方案已确认并实施。用户另行授权 Eino→Codex 和原生 Codex 各一次真实只读冒烟测试，关闭重试、工具上限为 0；这两次账号链路验证不代替真实产品任务质量或多人试点验收。
