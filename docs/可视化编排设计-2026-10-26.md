# Pangu 可视化编排设计

日期：2026-10-26。范围已确认：按推荐范围直接实现，覆盖现有执行能力。实现与测试记录见《可视化编排使用》。

## 目标与推荐

用户通过添加助手、拖动节点、连接步骤、填写表单完成编排。创建、编辑、发布版本查看和运行入口均不要求编写或上传 JSON 文件。后台继续使用结构化 API 和 PostgreSQL 保存定义，Hatchet 按节点调度 Eino 与 Codex。

推荐以 Dify 的画布与配置面板为主要交互参照，借鉴 n8n 的连接操作；采用 MIT 许可的 React Flow 作为画布组件。它与当前 React + TypeScript 工程契合，已有节点移动、连接、缩放和键盘操作能力。仅引入画布依赖，不引入另一个工作流平台。

| 方案 | 取舍 |
| --- | --- |
| React Flow + Pangu 现有执行能力（推荐） | 完成实际可保存、可发布、可运行的可视化编辑；保留当前项目与版本模型 |
| 自研 SVG 画布 | 减少依赖，但需自行实现连线命中、平移缩放、键盘操作，交互维护成本较高 |
| 接入完整 Dify / Flowise 运行平台 | 可获得更广泛节点类型，但会增加执行引擎、凭据、权限和版本体系，不适合本次改造 |

官方参考：[Dify 工作流教程](https://docs.dify.ai/en/guides/application-orchestrate/creating-an-application)、[n8n 节点连接](https://docs.n8n.io/build/understand-workflows/workflow-components/connect-nodes-together.md)、[Flowise Agentflow V2](https://docs.flowiseai.com/using-flowise/agentflowv2)、[React Flow](https://reactflow.dev/index)。这些是适配依据，不是对行业产品的绝对排名。

## 页面与操作

```text
工作流名称                         未保存 / 已保存     保存草稿  发布  运行
┌──────────────┬──────────────────────────┬────────────────────┐
│ 添加助手      │                          │ 所选步骤            │
│ 搜索         │   产品规划 ── 代码实现    │ 名称 / 助手版本     │
│ 当前项目助手  │                 │        │ 输入字段映射        │
│ Eino / Codex │              只读审查    │ 执行条件 / 人工审批 │
│              │                          │ 问题与修复提示      │
├──────────────┴──────────────────────────┴────────────────────┤
│ 流程输入与预算             撤销 / 重做   自动排列   缩放 / 适配 │
└─────────────────────────────────────────────────────────────┘
```

使用现有界面的颜色、字体和中文术语；画布占据主要工作区域。节点区分 Eino 与 Codex，显示中文名称、已固定的版本、条件/审批标记。图中箭头表示“等待上一步完成”，字段传递在侧栏显式选择。

添加节点默认选择当前项目助手的最新发布版本，并立即固定引用。重新打开工作流不会静默升级助手；升级是用户明确操作。支持拖拽移动、连接/断开、删除、复制、撤销重做、自动排列、缩放和键盘操作。没有助手时给出准备入口。

点击节点，侧栏以普通表单配置名称、版本、输入映射、条件和审批超时。变量选择器只提供全局输入或直接上游的可用字段；有已声明结构时展示字段树和类型，无结构时允许表单填写字段路径并提示运行时仍需校验。类型不自动转换。

流程输入通过字段表单定义名称、类型、必填及对象/数组结构；调用次数预算通过数字输入设置。发布前显示问题清单，点击问题定位相关节点。发布版本使用只读画布查看；运行复用现有任务表单、预检、幂等提交与结果页；定时任务继续固定已发布版本。

## 保存与数据边界

- 草稿可保存尚未完成的编排，发布必须完整有效。仅对工作流草稿区分结构校验与执行校验，不放松项目权限、引用权限、请求大小及类型限制。
- 明确显示未保存状态；离开时提醒。首次采用显式保存，沿用修订号冲突检测，冲突保留本地编辑，不覆盖其他人的新修订。
- 节点坐标、显示名称与画布视图作为编辑信息，随草稿及发布快照存入产品数据库；执行编译忽略这些展示信息。旧工作流没有坐标时按现有依赖自动排列。
- 页面打开或重新读取时从服务端取得配置；浏览器编辑中的未保存内容不充当配置缓存，不用 localStorage 代替数据库。
- 删除节点或连接后检查引用，不静默改变条件或映射；允许撤销，未解决引用问题不得发布。
- 查看者仅能查看，归档对象不可编辑；助手只允许同项目的有效发布版本；后端仍是权限和发布校验的最终依据。

## 首版执行边界

覆盖现有最多 32 节点 DAG、串行与并行、条件执行、人工审批、字段映射和预算。条件保留现有布尔/字符串精确匹配；审批表现为 Agent 执行前的设置，不伪造独立执行节点。

现有引擎中，任一直接上游跳过会导致依赖节点跳过。因此不能把互斥分支连接到同一后续步骤，宣称实现“任一分支完成就继续”；编辑器应提示真实含义。Codex 并行与审批限制遵守当前后端规则。

本轮建议不扩展循环、子流程、任意脚本节点、独立 HTTP 节点和多人实时协作。它们需要另外设计执行语义和安全边界，不能只在画布上画出外观就宣称支持。

## 可独立执行的任务

| 任务 | 交付与验收 |
| --- | --- |
| V01 草稿与展示信息契约 | 新旧工作流可读取；位置和名称保存后可恢复；未完成草稿可保存但发布被拦截；跨项目引用继续拒绝 |
| V02 画布与助手库 | 无 JSON 完成添加、移动、连接、复制和删除；支持缩放、自动排列与撤销；拒绝自环、重复连接和循环 |
| V03 节点与流程表单 | 输入定义、字段映射、执行条件、审批、预算均可编辑；删除引用及切换版本不静默丢字段 |
| V04 保存、发布与运行闭环 | 草稿状态清晰；修订冲突不覆盖；发布只读视图与实际执行定义一致；可进入任务运行及定时计划 |
| V05 验证与交付 | TDD 覆盖映射、依赖、保存恢复、权限和发布边界；浏览器验证实际画布与表单；原生 Codex 独立审查；构建后部署本机 |

TDD、Git 管理与原生 Codex 审查沿用已确认约定，无需重复确认。真实模型验收仍遵守既有预算约束，编辑器验收不需要新增模型费用。
