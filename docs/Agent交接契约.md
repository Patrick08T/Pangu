# Agent 交接契约

日期：2026-10-27。用户已确认：草稿允许暂存，发布、试运行和正式新执行必须配置完整契约；旧版本和历史记录保留。

## 如何填写

进入“助手 → 助手名称 → 配置 → 交接契约”。五项均通过表单填写，每项最多 4096 UTF-8 字节。

| 项目 | 应说明的内容 |
| --- | --- |
| 交接目标 | 负责解决的问题及职责边界 |
| 输入与上下文 | 需要的任务输入、上游产物和资料；具体资料授权仍在本次任务中指定 |
| 交付物 | 报告、结构化结果或代码产物，以及格式要求 |
| 验收标准 | 可以核对的完成条件与证据要求 |
| 异常处理 | 输入不足、执行失败或验收未通过时返回哪些缺口和下一步 |

例如产品规划助手可以约定：根据已授权调研结果制定规划；交付目标、非目标、优先级、路线图与衡量指标；结论关联证据，假设显式标注；证据不足时列出待确认项，不编造承诺。六个内置模板已按各自职责填写契约，可在使用前调整。

## 保存、版本和运行

- 缺项草稿可以保存；界面列出缺项并禁用发布及试运行。服务器同样校验，不能绕过表单直接提交。
- 补齐后保存，可试运行已保存草稿；发布生成不可变版本。契约随版本参与比较、恢复、模板绑定与工作流编译。
- 已有 Agent 没有契约时，需要编辑草稿并发布新版本。工作流须重新选择该 Agent 版本并发布，定时计划再显式切换到有效版本；系统不会擅自改写旧发布配置。
- 历史记录保持可读，升级前已接受的任务可继续恢复、查询和以原请求键确认回执。使用新请求键、人工重跑、返工或新的定时触发均按必填规则处理。
- 无契约的旧定时快照会跳过并记录原因，释放活动槽，不造成永久等待；补齐并更新计划后可正常触发。

契约实际传给 Eino 和原生 Codex。权限、超时、重试、工具次数、预算和任务状态沿用现有运行配置。文字验收标准不是自动质量判定；结构化输出校验和真实验证证据仍独立生效。
