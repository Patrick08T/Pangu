# Pangu 迭代闭环改进设计

## 目标与已确认边界

依据运行 `50acec3c-21b8-4b88-ae53-7333a0c8f0ee` 的复盘，用户已采纳改进建议，并确认执行图或 Agent 调整采用新版本、保留成果续跑，历史运行保持不可变。继续采用已确认的 TDD、Git-only 约定；不提交或推送，不使用 Ponytail。代码审查遵循官方 open-code-review-delegate skill。

本次将执行完成与业务验收分离、补齐平台证据交接、校验获批计划与执行图、建立持久阻塞与定向恢复，减少无变化的重复核验。用户研究的下一轮方案写入路线图，不擅自联系外部人员。

## 状态与验收

保留引擎运行状态用于调度与取消，增加独立业务结果。使用终端节点已声明的 `iteration_complete`、`ready`、`status` 判断业务验收：只有全部适用终端明确完成且引擎成功才显示通过；缺失、跳过、部分完成和执行失败均不能推导通过。列表、详情、历史摘要一致展示，结果不靠节点名称或自然语言关键词猜测。

## 证据交接

每次执行从持久原始来源读取运行快照、固定版本与节点引用、审批决定和消费、检查点、尝试及命令证据、来源报告和用量。证据附带运行归属、采集时点、哈希及覆盖限制。审批消费先核验冻结输入，再注入运行期证据，避免实时数据改变审批主体。

Codex 在其独立 clone 的 Git 元数据目录读取平台生成的只读证据文件；这些文件不进入产品 diff，也不把密钥或浏览器权限交给模型。提示词仅携带索引，按任务需要读取相关报告。证据不是新增授权，旧失败和未证明记录保留。续跑证据明确区分当前运行与来源运行。

新增 `evidence` 模块负责读取数据库原始证据、生成索引及写入运行期 Git 元数据目录，仅依赖 database、diagnostic、workflow；scheduler 在消费审批后调用，api 通过既有项目读取权限公开索引。它不承担调度、审批或配置发布，不形成模块循环。

## 计划与执行

统一计划提供结构化任务到节点映射及执行图候选，平台校验引用、依赖、独立验收及权限边界。审批页面显示具体结构差异，与方向和任务在同一轮确认。批准后发布需要的新版本，以已核验检查点和可复用前缀建立后续运行；禁止改写历史定义。需要的结构变化未落实时，不能把旧图当作获批新图继续执行。

`execution_plan` 包含 `changes`（节点、依赖、任务指令与已发布 Agent 版本的调整）和 `assignments`（任务 ID 到执行节点的一对一分配）。新增角色通过已有 Agent 发布流程取得版本后引用，运行中不让模型自行生成无版本的角色权限。审批模块依赖 catalog、submission，在同一事务内发布版本、保存续跑意图并消费原批准；plan_continuations 保存来源授权。后续运行核对冻结图、原文、哈希和检查点后继承授权，界面明确显示原审批来源。发布需要 manage_catalog 权限；运行管理权限不会自动扩大。

## 阻塞与恢复

关键补证项必须有稳定标识、类型、负责人和解除条件。节点发现阻塞后，相关执行进入持久等待，不使用模型无限重试业务缺口；已完成的检查点、报告和人工纠偏保留。补证后只复验受影响节点，恢复动作仍受项目权限、取消、内容一致性与显式预算约束。等待不自动过期。

没有文件变化且没有新增证据时，复验复用原检查及其版本归属；存在新的关键证据时不能以文件树相同跳过独立核验。最终验收保持独立。

## 验证

先复现部分验收显示成功、角色缺少已有平台证据、计划依赖不匹配仍实施以及阻塞后重复执行的问题。验证范围包含 Go 契约与独立数据库测试、前端状态和审批交互、真实 Hatchet 的持久等待与续跑；模型使用测试替身。前端构建完成后才进行嵌入式 Go 构建。

本地升级前保留二进制与配置备份并检查活动模型任务；验收后为旧运行补证并定向复验，旧报告保持原文。发布与续跑实际结果另记验证文档。
