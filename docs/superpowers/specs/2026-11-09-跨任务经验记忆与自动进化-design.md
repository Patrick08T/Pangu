## 选定方案与模块边界

采用现有 PostgreSQL 保存结构化经验。首版以项目、角色、模块、版本条件、错误特征和关键词检索，不新增向量数据库、知识图谱服务或模型微调管线。单纯角色笔记文件不便执行权限、撤销和并发控制；独立记忆服务在当前规模下不是闭环所必需。

新增 `internal/experience`，集中负责经验原文、版本、状态、来源和使用记录。它依赖 database、diagnostic、workflow；权限与身份校验由现有 identity 在调用边界执行，并在有副作用的事务中重新检查。scheduler 编排提炼、复验、候选生成和晋级；evaluation 负责套件、实验及判定；catalog 负责版本可见性和发布；不新增第二套调度框架。

在 `workflow` 定义纯数据的经验引用及输入结构，agent 只消费已授权输入，不直接检索全库。新增模块依赖先登记到架构测试。所有配置从原始数据库读取；索引只负责定位，配置重载必须重建相关索引，不缓存配置正文。

## 启用与授权

默认所有既有项目、角色、工作流和入口均未开启自动进化。项目管理页提供一份有修订号的学习策略，启用时必须明确保存以下内容；缺项可以保存草稿，但不能启用：

- 项目和允许学习、优化的角色对象列表；允许升级的工作流对象列表。
- 允许自动切换的具体入口：工作台的项目运行入口、指定定时计划或指定 Webhook；工作流授权不自动授权其全部入口。
- 已发布的提炼与候选生成角色版本、允许使用的验证环境；不默认升级模型或创建额外共享角色。
- 独立学习预算与独立评测预算、预算周期和候选生成间隔。沿用现有调用种类，额度必须显式填写；无额度不启动，不恢复业务任务的隐式默认上限。
- 已冻结的评测套件、独立保护集与保留集、样本分组及重复次数、唯一主要改进指标、最低改善幅度、非劣效界限、不确定性判定方法与置信水平；同一保留集允许验证的候选次数及多重比较控制方式。
- 经验投放模式、授权试用的任务范围与流量上限、收益验证条件；未明确试用范围时只允许隔离影子评测。
- 观察窗口、最少有效观察样本、最长观察期限、退化门槛、经验保留期限和来源证据的保留授权。

策略管理、自动发布分别要求项目管理及共享目录管理权限；定时与 Webhook 的变更还要有对应管理权限。保存策略的授权人、修订、范围及撤销状态持久记录，后台不能使用一个绕过项目权限的隐含管理员。每次读取经验、派发、发布和入口切换都重查权限；授权撤销后停止后续动作，正在执行的模型停止沿用现有取消与停止确认机制。

既有人工审批继续约束业务实施。自动进化授权不代替业务任务的逐项批准，不允许扩大写入范围、部署范围或验收门槛。

## 数据与记忆生命周期

经验原文是独立数据源，不是运行日志缓存。每条经验的内容版本不可变，修订产生新版本；生效、替代和撤销状态可更新并写审计。

| 数据 | 必须保存的内容 |
| --- | --- |
| 经验版本 | 项目、稳定条目 ID、修订、类型、适用角色与条件、观察到的问题、经验证做法、反例与限制、来源引用和内容哈希 |
| 有效状态 | candidate、active、superseded、revoked、expired；active 表示主张通过独立复验，不等于已获准默认注入；保存验证记录、失效原因、保留授权与期限 |
| 投放状态 | shadow、canary、serving、paused；保存适用范围、确定性分组规则、收益实验、观察结果及变更修订，与有效状态分别管理 |
| 使用记录 | 业务运行、节点、循环轮次、审批代际/修订、逻辑输入指纹、经验水位及版本清单、投放分组、检索依据、实际注入哈希；采用说明与后续结果分开保存，不把“被检索”当作“有效” |
| 成果依赖 | 输出/规划/补丁/检查点 ID 与哈希、有效输入指纹、直接经验清单及上游输出引用、失效原因与代际；传递依赖可回查，不复制来源正文 |
| 学习意图 | 来源运行、证据修订、策略修订、处理阶段、幂等键与意图代际、对应提交回执、错误与下次可重试状态 |
| 对照实验 | 实验身份、对照臂、逻辑项目及隔离环境、旧版本、候选内容哈希、编译结果哈希、冻结记忆清单、套件版本、每例每次尝试、机器判定与原始证据、预算及保留集使用次数 |
| 晋级记录 | 来源经验、实验、发布版本、适用项目、目标互斥记录、逐入口的旧值与新值、当前采用版本、最近稳定版本、观察样本与截止条件、切换与回退状态 |

经验首先区分事实观察和修复建议。错误退出只证明该次执行失败，不自动证明原因；成功退出也不自动证明一项宽泛结论。修复建议只有在声明的适用条件内获得独立检查证据后才能生效。模型自述的信心不是生效标准。

相同适用条件出现冲突时保留来源和反例，不按“最新一条必然正确”覆盖。能由确定性证据判断的冲突修订旧经验；证据不足的冲突候选保持未生效。只有用户明确表达的偏好才可记为偏好，不能从网页、代码注释或他人的消息推断用户授权。

## 提炼与生效流程

1. 后台对账发现业务运行已终结且 StopConfirmed 后，持久保存学习意图。扫描和分页必须覆盖完整记录，不依赖用户打开详情页，也不只读取首屏的尝试或报告。
2. 学习意图以来源运行、证据修订和策略修订去重。学习、候选生成和评测任务带明确 purpose，不再触发学习，防止递归自增。
3. 提炼角色只读原始证据，输出结构化候选、明确主张及来源；不直接写生效经验、不改变角色、不发布配置。新人工反馈修正旧结论时建立新的证据修订，旧候选不会覆盖新事实。
4. 平台校验来源归属、哈希、授权、保留期、敏感信息和输出结构。无有效来源、截断后无法支持结论、引用答案或工具日志中的指令，均不能生效。
5. 用预登记的独立检查复验候选主张；生成候选的角色不能修改检查器或预期结果。只有可在现有验证环境中验证的经验转为 active，初始投放状态为 shadow；无法形式化或需要外部授权的经验保持 candidate 并说明原因。
6. 验证事务同时保存验证结果与经验状态；重复回执返回同一结果，回执还必须匹配意图代际。提炼或复验失败只影响学习意图，不改写原业务运行的成功、失败或验收状态。
7. 将“主张成立”和“注入有益”作为两个门槛。shadow 仅在隔离环境进行无经验基线与有经验候选的配对实验，不额外重放生产副作用。通过预登记的收益与保护门槛后，方可在明确授权的 canary 范围试用；未获得试用授权时保持 shadow，不把“经验正确”当作默认注入许可。
8. canary 以持久化的任务分组和流量上限控制，单任务重试不改变分组；人工审批照常执行。观察达标才转为 serving；收益不足、样本不足至最长观察期限或出现退化时暂停投放。暂停投放不必否认主张本身，但权限、来源或主张失效必须同步阻断使用。同一实验中的经验组合保持冻结，组合收益不自动归因到每条经验，也不外推到任意组合；已知冲突组合不得同时注入。

每条经验最多 2 KiB，超限要求提炼任务缩小主张，不静默删掉适用条件或反例。原始报告保持在现有证据存储，不复制到经验正文。第一版不批量追溯全部历史运行；管理员明确选择的历史记录可通过同一有预算流程回填。

## 检索、注入与可复现性

新业务任务接收时固定角色/流程版本、学习策略修订和可选择经验的版本水位或不可变集合，并记录当时的投放范围；不在此时提前为所有节点选满经验。水位必须能还原可选版本与当时投放修订，不能只是依赖可变状态的时间戳。后续新增经验及投放扩围不进入该任务的原代际；撤销、过期和来源授权失效始终优先于冻结。

节点完成 BindInput、获得真实 Parameters、Parents 和已有错误反馈后，在模型执行与审批主体冻结前选择一次经验并持久化。逻辑输入身份包含运行、节点、循环轮次、审批代际/修订和绑定输入指纹；同一身份恢复或重试沿用原选择，新轮次或人工纠偏后的新输入可在原水位内重新筛选。每节点最多 4 条、总正文最多 8 KiB，先按权限、项目、有效状态、投放范围和适用条件硬过滤，再按错误特征及关键词排序；稳定 ID 用于确定性排序。普通任务只选 serving，获准试用任务可选对应 canary，shadow 不进入生产输入。无可靠匹配时注入空集合，检索故障必须报告，不能伪装为“没有经验”。

每次执行从经验原始版本读取正文，并重新验证授权、保留期、撤销与依赖状态。相同逻辑输入的恢复不临时换成更新经验。普通版本替代不改写已冻结输入，投放暂停阻止新的选择；确认依赖失效则按后述协议阻断原输入，而非静默去掉某条经验。冻结引用和哈希用于审计、重现，不作为绕过来源删除或权限撤销的缓存。

### 成果依赖与复用

有效输入指纹覆盖绑定参数、实际编译的角色/步骤指令、冻结经验清单及正文哈希、上游输出指纹和审批代际。输出、规划、补丁与检查点保存直接经验依赖和上游引用，可传递回查到来源；旧成果缺少必要依赖证明时不得按“无依赖”继续复用。

撤销或删除沿“经验 → 输出 → 检查点 → fork/后继运行 → 审批主体”传播。Prefix、检查点导入、审批继承、从持久化输出恢复及下游派发前均检查有效输入指纹和依赖状态，不能因复用节点跳过模型执行就跳过验证。先使依赖失效可见并阻断使用，再对账处理衍生成果；对账尚未完成不代表成果安全。若从最早受影响节点重跑，必须使用可证明未受影响的干净检查点/基线，不能仅删掉报告而保留旧工作区补丁。无法安全重建或已涉及不可重放副作用时阻塞并报告，不自动补偿已发生的业务操作。

### 系统失效与审批代际

增加独立的系统失效原因与 approval_generation。人工 changes_requested 仍表示人在同一代际提出纠偏；系统依赖失效记为 invalidated，不能伪造人工决定。审批唯一性与输入哈希绑定到“运行、节点、代际、轮次”，而不是在旧轮次原地替换输入。

在事务中比较旧代际并撤销其待处理或已批准未消费的 gate，同时记录失效原因和新的重建意图；重复事件返回同一代际结果，迟到的旧审批回执不能恢复有效性。新代际继承原角色/流程及授权边界，固定新的可用经验水位或明确空集合，按依赖图重建受影响的只读上游，持久化新经验选择与审批摘要后请求新审批。重建使用既有取消、StopConfirmed、提交和对账机制，不并发运行新旧实施分支，也不创建第二套业务执行状态机。

审批消费及实际派发前再次检查代际和依赖，覆盖“已批准但尚未消费”与恢复重试的竞态。已启动的受影响实施请求取消并等待 StopConfirmed；已产生的文件或外部副作用不因新审批而自动撤销。普通未审批任务明确报前置条件失效，通过显式新代际或重新提交恢复；同一旧输入重试不能跳过失效条件。

Codex 与 Eino 接收相同的结构化经验正文、适用条件和来源元数据。Eino 的显式输入组装同步新增经验字段；报告引用不代表模型已经读到原文，当前执行器没有证据读取能力时不得声称完成原文复核。整个输入继续遵守现有大小与敏感信息校验。

经验是任务资料，不拥有修改系统规则、授权、工具权限、预算、项目配置或验收标准的效力。每次运行可查看“使用了哪些经验、来源是什么、为何匹配”。是否有益由后续独立结果记录；一次成功不能直接归因于某条经验。

## 角色候选与项目隔离

自动候选只允许修改角色 `Instruction`。将该字段规范化后，节点其他字段必须与基线完全相等，包括模型选项、执行器、连接、权限、重试、交接契约、输出与完整报告契约、审批条件。未来新增字段默认受保护，避免遗漏字段导致自动扩权。

候选保存到实验记录，不能占用或覆盖用户正在编辑的共享草稿。候选基于固定角色版本与固定经验集生成；同一项目、同一角色对象的晋级互斥跨策略生效，覆盖评测、发布、入口采用与 observing，直至 stable、rejected 或完成 rollback。工作流及入口也有各自的目标互斥，防止不同角色实验同时改动同一目标。互斥是带版本的持久化占用记录，由对账恢复，不长期持有数据库事务锁；未完成的外部切换仍保留占用。没有新增有效经验或证据变化时，不反复生成相同候选。

自动生成的角色和流程版本附带来源实验及学习项目，版本内容和可执行性限于该项目。保持角色对象身份，避免复制同职责角色；公开的原共享版本仍可复用。列表、读取、导出、工厂角色选择、编译、发布引用及运行入口都必须执行版本范围检查，不能仅在检索经验时过滤。

当前 AgentChoices/RunnableChoices 按最高版本选择的路径要改为“当前项目可用且已确认稳定的版本”；候选、仅发布尚未稳定、被回退的自动版本不能成为通用默认选择。observing 版本只供受控评测或明确授权的观察入口使用，不能因已产生版本号而被其他业务入口采用。仅拥有其他项目权限的用户不能读取自动版本中的项目内容。管理员的跨项目管理权限不等于允许模型自动跨项目使用私有经验。

## 实验执行身份与隔离契约

未发布候选通过服务端的受控实验编译入口执行，不先发布、不写共享草稿，也不通过删除 VersionID/AgentVersion、伪造人工版本或关闭既有 CheckDefinition 来绕过一致性校验。普通运行仍只接受原有合法定义；实验分支必须从数据库读取获准实验身份及不可变候选，再验证其与基线的受保护字段差异。

实验身份至少包括 experiment_id、对照臂、candidate_hash、baseline_version、logical_project_id、evaluation_environment_id、purpose、策略修订和实验代际。服务端同时绑定套件版本、源码基线、工具/模型配置、冻结经验集、预算及编译结果哈希。角色试验用候选 Instruction 编译；流程试验复制完整 Flow，仅在许可绑定中解析到实验候选，并保留角色指令与步骤 Task 的真实组合。候选编译结果与后续发布内容必须一致，否则重新评测。

logical_project_id 决定经验、角色、套件和来源的可读范围，evaluation_environment_id 只决定测试工作区、沙箱、假服务和凭据；不能为换一个工作目录而换成别的业务项目，也不能让实验身份把生产资源权限带入隔离环境。环境由管理员登记并由服务端解析，客户端、候选生成者与模型不能选择任意目录或资源。

实验继续经 submission、scheduler 和 Hatchet 执行，具有独立 purpose、预算、取消与恢复语义，不触发经验提炼。机器结果按实验、对照臂、样例、重复序号、代际及执行输入哈希关联，不借用人工反馈或只能关联已发布版本的旧评测关系。回执身份不符、环境基线漂移或迟到旧代际结果不得参与判定。编译与工作区接口必须分别携带逻辑项目和执行环境；仅增加数据库字段而仍按业务 ProjectID 准备生产工作区不满足此契约。

## 独立评测与发布门槛

复用现有评测样例的明确保留授权；新增冻结套件与实验判定。区分开发集、保护集和保留集，目标任务、来源运行和重复输入族不能跨集合泄漏。候选生成者只能读取开发集反馈；保护集和保留集的输入及预期结果不提供给生成者，也不写入经验库。样本不足、套件失效或来源撤回时，实验不得晋级。

基线与候选在同一套件、相同项目基线、相同预算和同一冻结经验清单下配对执行。模型或工具配置变化则实验失效，不能沿用旧比较结果。用于验证“加记忆是否有效”的实验另设无经验基线，不能把角色改动与记忆变化混为一种收益。

检查器来自预登记的结构化断言或受控验证命令；实现侧重输出字段、行为约束、测试结果及可核对产物。检查器、保护测试、预期结果与判定配置置于候选不可写的受信边界，版本和哈希冻结；不能仅把可写仓库中的一条测试命令称为独立验证。评测环境限制挂载、网络及凭据，生成者不能读取隐藏答案或修改判定路径。普通 clone、临时 HOME、环境变量白名单本身不构成这种隔离。需要语义判断的模型评审只作为辅助证据；缺少可信判定方式的场景不进入自动发布。样例本来需要人工确认的事项不能由评测器冒充真人通过。

启用策略必须预登记主要目标、最少独立样本、重复次数、最低改善幅度、非劣效界限、资源容差、不确定性方法及置信水平，不使用隐藏默认阈值。以输入族/任务为统计单元，重复尝试保留配对和组内相关性，不能把同题多次尝试伪装成更多独立样本。晋级同时满足：

- 所有关键保护用例每次重复均通过，所有授权、隔离与结构约束通过；这类硬门禁不以平均收益抵消。
- 保留集的主要指标按更优方向计算配对差异，其预登记不确定区间下界达到最低改善幅度；普通质量指标及预登记关键任务分组同时满足非劣效界限。用预登记的统计判定替代“每组重复都必须改善”，但不放宽硬门禁。
- 用量、耗时和返修等非主要指标不超出策略声明的容差；费用或时延数据未知时，不能按该指标声称改善。
- 完整实验达到预声明的独立样本与重复次数。失败、超时和基础设施异常分别记账，按事先确定的规则重试或判定无效；不得丢掉不利样本、临时放宽门槛、临时换统计方法或无限重试刷过。证据不足即不晋级。
- 当前策略、角色基线、工作流基线、环境基线及经验依赖仍与实验一致。

保留集访问次数作为套件级受保护额度，在候选评测前原子预留；失败实验也消耗额度，换策略修订或实验 ID 不能重置。预登记最大候选数和多重比较/序贯检验方案，禁止反复看结果后挑最佳的一次发布。候选生成者只收到必要的通过、失败或证据不足结论及允许披露的阻塞类别，不获得隐藏输入、逐例错误或答案；最低披露仍算一次使用。额度耗尽需负责人独立补充/轮换保留集并重新授权，不能由优化器把同一批题改名后继续试。

可选主要目标仅限现有可观测指标：业务验收通过率、返修次数、调用费用、耗时。费用价格未配置或用量不完整时，费用目标不可启用。通过率持平且其他指标无可靠改善时不发布“优化版本”。首次启用需先建立基线，不能跳过冷启动。

评测使用隔离副本和测试资源，不重放真实发送、发布、支付、生产部署等副作用。依赖真人决定或未提供隔离验证环境的流程保持不可自动晋级，并展示阻塞原因。Perforce 项目不能直接在用户 Client 中回放实验；没有独立评测工作区时拒绝自动评测。

## 发布、工作流升级与入口切换

角色候选通过后，调用 catalog 的受控发布事务，保存不可变版本与来源实验；使用幂等键和基线比较，重启、重复回执不会重复发布。用户草稿存在未发布修改或基线在评测期间变化时，标记冲突并停止晋级，不覆盖、不合并猜测、不直接绕过草稿检查。

catalog 明确区分“人工草稿修订”和“自动实验”两种发布来源，各自有唯一来源约束。自动版本直接使用已核验的候选内容，不把项目私有指令写回共享草稿的 Spec；记录其公共来源基线及项目内前序版本。发布、默认选择和可见性不能仅凭全局版本号最大值判断。自动工作流版本采用同样的来源与范围规则。

角色发布与工作流采用分开记状态。对每个获准工作流复制原始完整 Flow，仅替换命中的 AgentVersion，保持 Task、Schema、ReadOnly、审批、条件、绑定、loops、预算、编辑信息及其他字段。按角色指令与步骤任务追加后的真实编译结果运行该工作流的保护集和保留集。与步骤任务冲突、质量下降或缺乏可执行评测时，该工作流继续原版本，角色已发布不等于该流程已升级。

通过流程评测后发布新的不可变工作流版本，再切换授权入口：

- 项目工作台：通过项目入口的采用绑定选择后续任务版本；普通默认使用稳定版本，授权观察范围可采用 observing 版本；用户显式指定历史版本时不替换。
- 定时计划：核对创建人权限、计划修订及当前版本后更新未来触发定义，沿用现有远端对账；已接受的触发快照不变，暂停或删除的计划不因升级恢复。
- Webhook：核对入口归属、启用状态和当前版本后切换；同一 delivery ID 仍返回原回执，不因版本升级重复派发事件。

每次切换都比较入口当前值与本实验期待值。人工作出的后续编辑产生冲突时，停止该入口自动切换并报告，不覆盖新决定。数据库中的版本、切换意图与审计在事务中保存；远端定时更新不假装与数据库原子完成，由既有对账机制恢复。副作用任务与回执必须带目标、幂等键和意图代际，执行前重读当前授权与期待值，完成时再次比较代际；旧代际不得将新意图标记成功。外部状态存在歧义时先读取核实再重试，不能盲目重复副作用。已运行、排队、审批中的任务不因普通版本发布而变化；依赖失效时按前述协议阻断并生成新审批代际。

### 稳定晋级与观察互斥

发布版本、入口 adopted_version 和最近 stable_version 分开保存。候选通过离线门槛后发布，获准入口切到新 adopted_version 并进入 observing；stable_version 仍指向上一稳定版本。仅在观察窗口、有效样本及质量/资源门槛全部满足后，比较目标修订并原子推进稳定指针。发布或首次切流本身不能把新版本标为稳定。

同一项目/角色的晋级占用持续到相关观察目标全部稳定或已明确拒绝、冲突退出、完成回退；不同策略不能越过该占用晋级下一个版本。工作流/入口目标占用按固定顺序短事务获取，冲突即退出本次获取并稍后对账，不持有部分占用等待其他目标。失败或过期不能只删占用：先终止旧代际派发、确认停止并核实外部切换结果，持久化终态后再允许下一实验。

样本不足在最长观察期限内保持 observing，不声称收益；到期仍不足则以“证据不足”关闭观察并回退仍由本次晋级控制的未来入口，不改写历史结论为“已证实退化”。如果没有获准且可执行的观察路径，该目标不得进入自动稳定晋级。每个入口的观察、冲突和回退独立展示，角色或某个流程通过不代表其他目标已通过。

## 退化、撤销与清理

每次晋级记录上一个稳定版本和所用经验。观察窗口内按策略声明的可比较任务与独立检查判定退化；样本不足保持观察，不凭一次无关业务失败推断模型变差。确认违反权限或关键保护约束时立即停止该自动入口继续采用新版本；达到退化门槛时回退未来任务绑定。

回退同样采用基线比较，仅撤回当前仍由该次晋级控制的入口。已经被用户调整的入口保持现状并报告冲突。回退不删除历史版本，也不撤销已经产生的业务文件或外部副作用。

经验撤销、授权撤回及来源删除通过可追踪关系使衍生经验失效，并检查蒸馏版本、实验、输出、规划、补丁、检查点、fork/后继运行及审批主体；不能仅从检索列表删除经验却让其影响继续隐藏在角色指令或复用成果中。依赖失效的自动版本停止用于新任务，未消费的成果与批准禁止继续使用，进行中的受影响任务取消并确认停止。按来源图与前述代际协议重建或阻塞，入口回退到仍有效的稳定版本；没有有效回退版本则暂停该自动入口并说明原因。

经验正文和自动版本内容遵循独立、明确授权的保留期限。普通来源日志清理前，只有已获长期保留授权的脱敏最小证据可以继续支撑经验；仅有哈希不能替代证据。未获授权或明确要求删除来源时，删除衍生正文并保留不含敏感内容的审计元数据，不以摘要或历史快照绕过清理。正文清理后的版本保留“已失效、不可运行”标识；不以原版本号提供经过静默改写的新可执行内容。新用途必须重新取得授权并建立新版本。

实现时将不可变版本身份/内容哈希/来源元数据与可按授权清除的私有正文分离，以墓碑标记不可执行；清理经验派生的输出、审批快照等正文副本时采用同样约束。现有 [catalog 不可变版本迁移](<../../../internal/database/migrations/0010_catalog.sql>)直接禁止版本行 UPDATE/DELETE，需显式设计迁移与专用清理路径，不能关闭全局不可变保护或假定普通 UPDATE 可擦除私有 Spec。清理任务只删除被撤回或到期的正文，不重新赋予旧 ID 新含义；备份与导出副本沿既有保留策略处理，不承诺本地 tombstone 自动擦除所有外部副本。

## API、界面与运行维护

项目设置提供经验读取、学习与自动发布开关，以及目标角色、工作流、入口、预算、投放范围和评测套件配置。经验页分别显示主张有效状态与投放状态、适用条件、来源、验证、收益证据、使用记录及撤销操作；自动进化页显示基线与候选差异、授权范围内的实验对比、不确定性、保留集剩余额度、目标占用、观察截止条件、阻塞原因及发布/回退记录。隐藏逐例结果仅供独立评估权限读取，不因展示页面而泄露给候选生成者。

运行详情显示经验水位、实际选择、依赖失效原因、审批代际与学习任务回执；学习任务可取消，不阻塞原业务任务结束。发布结果分别展示“角色已发布”“流程已评测发布”“入口已切换或等待对账”“正在观察”“已稳定或已回退”，不能用一个成功标识掩盖部分完成。

API 沿用项目权限、会话 CSRF、修订冲突、幂等回执和分页。OpenAPI 与生成类型同步更新；API 客户端不能自行提交伪造的晋级结论或机器评分。禁用策略停止新学习和新晋级，不影响按原定义执行的业务任务；撤销授权则遵循前述停止与失效规则。

## 实施范围与验证

| 范围 | 必须到达的位置 |
| --- | --- |
| 持久化 | 经验有效/投放双状态、使用及成果依赖、学习意图代际、策略、实验身份/判定、目标占用、采用/稳定绑定；正文可清除与元数据不可变分离、迁移与重启恢复 |
| 执行输入 | submission 冻结可选水位、BindInput 后选择、workflow 输入指纹、scheduler 读取原文、Codex/Eino 实际载荷、系统失效与审批代际 |
| 成果恢复 | Prefix、检查点导入、输出恢复、fork/后继与审批继承的依赖验证；干净基线重建、取消与 StopConfirmed |
| 自动任务 | scheduler 后台对账与派发、usage 独立额度、purpose、取消、代际回执、受控监测和不递归学习 |
| 评测 | evaluation 冻结套件、受信检查器、实验编译、逻辑项目/物理环境分离、配对统计、无经验对照、保留集暴露预算与多重比较控制 |
| 配置发布 | catalog 原文读取、候选验证与编译结果一致性、完整 Flow 复制、版本范围、稳定默认选择、修订冲突 |
| 使用入口 | 工厂上下文、工作台、定时/Webhook 的未来提交、历史回执、采用/稳定指针、观察期互斥、已有审批与运行快照 |
| 用户界面 | 项目策略、有效/投放状态、实验不确定性、观察与预算、依赖失效/重审批、发布/回退；API 和前端类型同步 |
| 工程约束 | 架构依赖清单、函数不超过 70 行、中文文档、TDD 与 OCR 审查 |

按以下依赖顺序实施，每阶段有单独验收，全部完成才交付“自动进化”，不能把后续阶段作为无期限扩展：

1. **基础契约**：先以确定性替身完成实验身份与隔离编译、经验/成果依赖、审批代际和故障恢复的失败测试，补齐观察期互斥及正文清理模型。此时不启用真实自动发布。
2. **记忆收益最小闭环**：选择一个有可信机器判定的场景，完成提炼、复验、shadow/授权 canary、Codex 与 Eino 跨任务复用，以固定角色的无经验/有经验配对实验验证收益。证据不足停在本阶段，不把接通存储等同于学习有效。
3. **角色蒸馏与受控采用**：在第二阶段达标后完成候选 Instruction、受保护评测与自动发布，再完成获准完整 Flow 评测、入口切换、观察转稳定和回退。角色发布、流程采用与入口观察分别验收，不以某一环节通过代替完整交付。

先写失败测试，至少覆盖：

1. 两个独立运行共享同项目经验，其他项目及过期版本不可读取；Codex 和 Eino 均实际收到相同语义上下文。
2. 提炼者伪造来源、证据哈希、验收结论、权限或用户偏好时不得生效；验证者不能修改被测代码或判定标准。
3. 重复事件、重启、取消和预算耗尽不造成重复学习、重复发布、递归学习或原任务结果变化。
4. 空保留集、重复输入泄漏、未知指标、漏掉失败样本、保护用例失败、未达到改善幅度时不得晋级。
5. 只允许 Instruction 改变，未来新增节点字段默认受保护；角色指令与步骤 Task 冲突能被实际流程评测发现。
6. 流程升级保持完整 Binding、loops、预算和审批；未授权流程、入口及其他项目的角色选择不改变。
7. 审批期间经验撤销、发布期间用户修改草稿、入口被人工改动、来源被删除时，旧授权和旧比较结果不能继续使用。
8. 事务中断与远端对账恢复后，只有一次有效晋级；Cron 与 Webhook 旧事件仍返回原固定版本回执。
9. 退化回退只影响获准的未来入口；撤销经验能找出衍生角色版本；无有效稳定版本时明确暂停。
10. 界面能准确显示角色发布、流程发布、入口切换、观察与稳定的不同状态；用户可查权限范围内的原因、预算和验证证据，生成者无法经 UI/API 绕过隐藏集隔离。
11. 未发布角色/Flow 候选经实验编译运行实际指令组合；伪造实验身份、去掉版本引用、篡改受保护字段、跨项目读取或误用业务工作区时拒绝派发；生产副作用无法从实验环境触达。
12. 经验撤销后，已完成节点、旧规划、补丁、检查点、fork/后继运行与继承审批均不能绕过失效；缺失依赖记录拒绝复用，重建不能带入已失效补丁；正文清理后的版本不可运行或从其他快照还原私有正文。
13. 等待审批、已批准未消费、正在执行及恢复阶段发生失效时，旧代际回执无效；新代际重新选择并审批，人工 changes_requested 语义不变，重复撤销只产生一个重建意图，新旧实施不并发。
14. 下游绑定参数、上游产物和循环错误反馈可参与经验选择；同一逻辑输入重试完全一致，新轮次只在原水位筛选，任务接收后新增经验不偷偷进入原代际；检索故障不等于空结果。
15. active + shadow 不进入普通业务输入，canary 只覆盖授权分组且重试不改变分组；主张成立但无收益、观察样本不足或退化不得转 serving；一次业务成功不能归因为某条经验有效。
16. 随机波动按预登记配对方法、独立样本与不确定性判断，不要求每次都改善，也不允许平均收益抵消保护失败；基础设施异常、费用未知、独立样本不足均按声明规则处理。
17. 并发候选原子消耗保留集额度，失败或更换策略/实验 ID 不重置计数；阈值、检查器与统计方法不可被候选修改，隐藏输入、逐例错误与答案不能泄露给生成者；同一题多次重试不能充当独立样本。
18. v2 观察期间 v3 不能通过其他策略晋级同一目标；首次切流不前移稳定指针，观察到期无充分证据时回退；旧发布/切换回执、重启对账及部分目标冲突不覆盖新意图，目标占用只在终态确认后释放。

验证采用 Go 单元与独立数据库集成测试、架构检查、前端交互与构建、真实 Hatchet 对账及恢复测试。模型先用确定性替身验证控制逻辑，再在明确学习预算和隔离样例内进行真实模型对照，不能把替身测试称为进化收益验证。

### 2026-11-10 采纳评审建议

在直接读取现有实现及官方 SuperAgent 文档后，用户采纳本轮建议，修订集中于：

- **先补执行契约**：未发布候选的服务端实验身份/编译、逻辑项目与隔离环境分离；经验到成果/检查点的传递失效；系统失效和人工纠偏分开的审批代际。
- **再证明学习收益**：主张验证与 shadow/canary/serving 投放分离；无经验对照、配对不确定性和非劣效门槛；保留集暴露预算与不可修改的受信检查器。
- **保证可复现与回退**：任务接收冻结可选水位，BindInput 后选择；同输入恢复固定上下文；观察期目标互斥、采用/稳定指针分离、意图代际回执及正文可清理模型。
- **有边界地借鉴 SuperAgent**：采用摘要加授权追溯、确定性路由、持久化副作用意图与独立监测思想，不照搬热更新提示、宽权限执行、无界历史保留，也不引入第二套调度器。

预算、样本量、统计阈值、试用流量及对象范围仍由管理员显式配置，缺项不得启用，代理不猜测实际值。新增验收用例是后续实施必须完成的测试要求，不是本轮已经运行的测试结果。

本轮仅修订此设计并检查内部一致性与文档差异，不修改实现、不启用自动学习或发布。后续实施继续使用 TDD，并按 open-code-review-delegate 完成逐文件审查。真实模型收益、运行成本、自动发布与自动回退均尚未验证；设计评测门槛只能限制已覆盖场景，不能保证所有未来任务永不退化。
