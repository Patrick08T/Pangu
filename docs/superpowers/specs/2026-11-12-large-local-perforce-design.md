# 大型本地 Perforce 工作区适配设计

状态：用户于2026-11-12确认“按此方案实施（推荐）”，包括35分钟清单预算、单次快照/结束取证各2小时上限、取消后继续有限取证规则。进入TDD实现；尚未部署或业务重提。

## 1. 目标与边界

- 修复 Partopia 百万级本地 P4 清单和快照链路，然后只再提交一次已授权的 GM/spawner 原需求。
- “保留业务文件范围”沿用原有集合：已同步文件、已打开文件、P4 未忽略的新文件的并集。不会扩大为忽略 P4IGNORE 的全盘扫描，也不会缩小项目 Scope、修改 Client/View/ignore 或只挑代码目录。
- 唯一新增排除项是用户已授权的**嵌套 `.git` 元数据**：目录本身及其内部、或 gitdir 指针文件；不读取指针目标、不改动或删除原文件。嵌套仓库的普通内容、`.gitignore`、`.gitattributes`、`.gitmodules` 等仍按原 P4 集合规则保留。
- 根目录 `.git` 仍拒绝，避免把根 Git 工作树混作本地 P4 项目。排除判断只用于快照清单；交付和 shelf 的严格路径验证不得因此放宽。
- 保留 #have、绑定、Host/Root/AltRoots/View/Stream、路径/链接/特殊文件检查、失败和取消取证、原 changelist 归属及人工审批。不会伪造 Ready 或使用不完整清单。
- 无产品数据库迁移、无 UI 改动、无源码上传、不部署未发布的经验/进化功能、不修改 Codex/Hatchet/索引/用户 P4 工作区。部署只基于已逐字节复现的旧版本及明确白名单补丁。

## 3. 方案比较与选择

**推荐：完整性优先的本地 P4 专用通路。** 保留权威全量清单；流式将明确验证的普通文件字节送入 Worker 自有 Git 对象库；单次运行只有一个无 checkout 的对象库；各次快照保留独立不可变提交。消除无用复制和整份输出缓存，但不通过猜测文件未变化而漏读内容。

其他方案不采用：

1. 仅提高8MiB、16MiB或30s：仍会遇到嵌套仓库被 Git add 当作 gitlink、重复复制及结束取证瓶颈，不构成完整修复。
2. 基于 mtime/size、opened 列表缓存快照：会遗漏未打开修改、恢复时间戳、外部 P4V/编辑器变更。可靠 Windows USN/监听加速需要连续性证明、全依赖覆盖和丢失回退，是独立后续项目。本次不引入长期缓存、跨运行共享对象或新后台服务。

代价：每次完整清单和内容校验仍可能需要较长时间；不会承诺百万文件快照能在一分钟内完成。

## 4. P4 清单与排除规则

- 保持 fstat -Rh / fstat -Ro / reconcile -n -a -l 的完整并集、顺序和 ignore 语义；没有自动重试、没有 -I、没有真实 reconcile 来获得清单。
- 从 localName 提取共用的严格规范化检查，新增清单专用分类结果（保留/排除/错误）；不以空字符串或吞错表示排除。localName 和 ShelveLocal 继续严格拒绝元数据。
- 在排除前检查所有路径分段、Unicode、命名空间、边界和歧义；`.git` 后的错误也不能被隐藏。Windows大小写和编码路径纳入测试。
- 对被排除项只验证到元数据标记的已存在祖先链，拒绝 junction/symlink/特殊文件；正常嵌套 .git 目录或普通指针文件允许排除，不下钻、不跟随目标。
- 一次清单建立不可变命令会话：冻结配置、工作目录、程序路径和已净化环境；该次调用共享 info/charset 能力，但每个命令参数仍单独校验。跨快照不缓存清单或 info。
- 超时、无效JSON、晚到错误、预算超限、路径异常或退出非零均失败，不返回部分列表。记录分阶段计数和耗时，不记录全量文件名或凭据。

## 5. 快照与仓库布局

### 5.1 单运行单对象库

- 新本地 P4 运行使用 Worker 管理目录下一个普通 `.git` 布局仓库，空工作树、不 checkout、不借用用户 Git 对象，不使用 alternates/hardlinks。
- 初始化仍在私有 staging 中完成，完整性检查后原子发布到 run/base；只在提交/树/对象可用、绑定复核成功后设 ready=true。
- 统一仓库定位函数，兼容旧 source+base 布局；不迁移或删除历史基线。新旧布局中失败恢复都校验实际对象，不能仅相信文件夹存在。
- 本地 P4 fork/rerun 子运行保留独立可达对象副本，但不 checkout；保留源 Lease。普通 Git 和历史隔离 P4 的 Clone/工作副本语义不变。

### 5.2 明确的普通文件字节导入

- 不再对原 P4 目录执行 git add：物理存在的嵌套 .git 即使被清单过滤，仍可能触发 Git 的 embedded-repository 行为。
- 使用受控 Git fast-import 流，将经过检查的普通文件以明确路径、模式及原始字节写入独立临时提交；路径正确转义，逐块流式读取，不把大文件或全量内容装入内存。
- 始终禁用 hooks、filters、textconv、LFS转换和自动换行；`.gitattributes` 是普通 P4 文件内容，不执行其中规则。P4专用树验证拒绝 gitlink 和非法路径；普通 Git 的 LFS/submodule拒绝策略不变。
- 每次仍读取应纳入的完整字节集合；Git对象按内容去重。不得仅依据 size/mtime 判断文件内容未变。性能验收包括无变更第二次捕获的磁盘增长，不能先假设 fast-import 的瞬时占用。
- 前后验证已打开文件的普通文件属性、身份和大小/时间变化；检测到漂移则拒绝本次提交。保留根和映射前后复核。Pangu锁不能冻结外部编辑器/P4V，本设计不是原子文件系统快照；真实演练期间需避免并发 sync/编辑。
- 文件系统元数据校验每项/数据复制每块检查 context；不会将无法中断的OS文件系统调用描述为硬实时可取消。
- 完成后流式验证树与对象，再发布引用；失败只留下不可发布的暂存/未引用对象，不改变成功 head 或用户文件。临时引用/文件由限定路径的清理处理。

## 6. 时间、内存与磁盘预算

这些是首版有限上限，不是已测得的性能承诺；较短的父 context 始终优先：

| 阶段 | 初始上限 |
| --- | --- |
| 一次清单的 info | 45秒 |
| 单个 fstat | 2分钟 |
| 完整 reconcile 只读发现 | 30分钟 |
| 完整清单含排序/验证 | 35分钟 |
| 单次普通文件元数据/身份验证 | 30分钟 |
| 本地快照 bulk Git 导入/对象复制 | 60分钟 |
| 单次完整快照（总上限） | 2小时 |
| 节点结束取证/恢复（总上限） | 2小时 |

- 快速预检查20s/28s、HTTP30s、普通Git查询30s、原展示/导出限制不变；不全局抬高超时。
- P4已有4个资源上限保留。Git清单/变更流同样设单条1MiB、原始总512MiB、条数200万、路径总256MiB；诊断输出4096字节。256MiB不是进程RSS上限。
- 重任务有分阶段进度和周期计数；“暂时没有stdout”不触发伪挂死判定。
- P4/Git进程使用受控生命周期、取消并等待退出，保留首个根因；继承管道/后代清理以测试证明能力，不把 WaitDelay 宣传为杀死所有后代。
- 所有存储仅位于现有 Worker 管理根，不自动改到 E盘，不动产品配置。完整清单后先得到实际文件字节S、路径P、数量N，预留余量 R=max(10GiB,目标卷容量5%)。首次演练按 `2.4*S + 4096*N + 2*P + R` 作保守空间准入，覆盖单对象库和暂态重复写入估计。
- 导入期间持续检查剩余空间和本次写入；低于R即失败，不能耗尽磁盘。演练实测峰值必须落在准入估计内；否则修订估计并重验，不能跳过门槛。
- 若现有卷不足，明确报告所需空间，等待用户指定存储变更；不静默缩范围、挪历史目录或放宽路径安全规则。

## 7. 结束取证、归属与展示分离

- before、after、local_commit、成功head仍是不同事实；before在模型运行前持久化，失败/取消也尽力保留after和归属，只有成功发布事务才能改变成功head。
- model未确认停止时仍不取证/发布。取消模型不等于结束取证已完成：结束取证使用独立有限预算，可在模型停止后继续读取；不会因取消而回退用户文件。
- 取证/归属未完成保持 p4_tracked=false，阻止下一次本地写操作，沿用恢复入口；不虚报成功或已完整跟踪。
- 新增内部流式变更路径枚举，安全跟踪不再调用带1000文件展示限制的 filesBetween；完整受预算控制，不取blob内容，仅获得变化路径。
- TrackLocal 按原 changelist 分组、有界分批 reconcile，保留既有归属、不自动 reopen。真实写入仍仅在原执行/取证流程授权处发生，不用于诊断探针。
- 产物仍取 local_commit，包括失败/取消后的现场；UI1000文件、单blob10MiB、diff1MiB、导出总100MiB等保护不放宽。超出交付范围明确报错，不丢弃内部安全取证。

## 8. 验证与发布门槛

1. 行为RED后实现GREEN：超过8MiB/16MiB合法流、晚错误、四类预算、零输出慢扫描、取消/退出与清理。
2. 嵌套 .git 目录/指针文件及其普通内容；根.git拒绝；Unicode/大小写/长路径/编码；范围外、歧义、junction/symlink/特殊文件；delivery仍拒绝元数据。
3. 真Git验证原始字节、无gitlink/filters、同size+mtime内容变化、删除/重建、部分导入取消、无变更二次捕获和空间增长。
4. 无checkout仓库兼容 diff/show/blob、审批/重试/失败现场、独立fork和旧布局；独立测试DB验证准备/恢复/事务门槛，不用产品DB跑集成测试。
5. 超1000变更可完整内部跟踪，但展示/导出仍按原限制失败；不动原changelist的批处理契约测试。
6. 真实 Partopia 完整只读枚举+容量统计通过后，在独立 Worker 管理的演练目录做完整捕获及无修改二次捕获；不创建业务运行/模型调用/P4写操作/产品DB记录。保存阶段耗时、数量/字节、峰值内存/磁盘、排除计数、tree无gitlink和取消证据。只有这一步通过才具备提交条件。
7. 对已核验旧源码/旧UI白名单叠加构建；回归、独立审查、索引指纹比对、运行中任务检查通过后，备份并替换原安装路径；健康失败回退应用二进制。回退不删除用户修改、changelist或不可变证据。
8. 浏览器明确选择 Partopia、原工作流v2、原中文输入、原implement人工审批；只点击一次开始执行，核实建立基线及业务节点启动，不把“提交202”当作业务成功。

## 9. 工程分工与非目标

- P4清单/排除/分批归属与测试为一组；受控Git流与文件导入为一组；仓库准备/恢复/事务和预算接线为一组，接口先冻结、重叠文件通过依赖串行。
- 不引入USN/watch缓存、新数据库模式、新公开API、跨run共享对象、全盘忽略规则重写或通用导出重构。
- 设计文件不暂存、不提交，以遵守用户原索引保护边界。实现前需确认本设计；当前源码仍为昨晚已测试但未部署的7文件候选。
