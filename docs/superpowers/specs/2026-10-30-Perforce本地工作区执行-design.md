# Perforce 本地工作区执行

## 已确认范围

用户要求 Perforce 项目也必须绑定本地目录，并明确选择：直接在绑定工作区执行；保留已有未提交修改，先留快照，原 changelist 归属不变，新打开文件进入本轮 changelist。本设计替代此前独立 Client 方案的新运行行为。历史运行及其交付证据不改写。

## 目录绑定与预检

项目 source 必填，填写绑定 Worker 上现有 Client 的 Root 或 AltRoot。执行目录为 source + scope。项目页面支持登记及编辑既有项目的目录绑定，管理员通过 PATCH /projects/{id}/workspace 保存。保存前在绑定 Worker 上只读检查目录、Host、映射、登录和已同步文件；项目有待派发或未结束任务时拒绝改绑，旧值校验防止覆盖他人的更新。

P4 命令显式指定绑定目录，防止 AltRoot 环境读取其他根目录。拒绝目录链接跳转及项目范围外的文件。凭据继续从 Worker 的 P4 登录票据读取，不写入页面或数据库配置。

## 执行与保留

1. 初次运行和每个代码节点执行前，在平台托管目录建立 Git 内容快照，用户工作区不创建 .git。包含已同步文件、已打开文件和 P4 未忽略的新文件；不把被 P4 忽略的构建输出纳入快照。
2. Agent 直接在本地项目子目录执行，读取已有修改。其修订信息指向外部内容快照，不要求本地有 Git HEAD。平台证据位于独立临时目录，仍校验完整性。
3. 同一 Worker 的本地 P4 操作串行；执行器尚未确认停止时拒绝新操作。模型失败、取消均保存现场，不能自动 sync、clean、revert、submit 或修改 Client。
4. 节点差异中的未打开文件 reconcile 到本轮待提交清单；已打开文件保持原清单，删除或恢复文件时同步正确的 P4 操作类型。只读节点意外修改时保存并登记现场，但拒绝发布成功检查点。
5. 进程中断或跟踪失败通过持久标志识别。确认旧进程停止后，下一次执行或交付先补齐前一尝试快照和 P4 文件归属，再继续。已完成节点沿用平台检查点；失败节点重试基于保留的本地现状。
6. 新运行以当前本地状态起步。成果复用要求现场与选定检查点内容一致，否则拒绝并提示新运行，不回退文件冒充旧基线。

## 待审核交付

结果页面展示绑定目录、本轮清单及涉及的原清单。原清单中的修改不自动迁移或 shelve 到本轮清单，页面加粗提示在 P4V 一并审查。平台仅 shelve 本轮曾跟踪的文件；清单混入其他文件，或现场内容在运行后发生改变时，拒绝把新内容交付为旧成果。中断但已确认停止的现场可补齐后直接交付，无需再次调用模型。

待审核清单和交付证据保留；清理平台产物不能删除用户的 Client 或本地目录。Git 项目继续使用独立执行副本。

## 边界

- 平台锁只协调 Pangu 自身操作，无法锁住外部编辑器或 P4V。任务执行期间对同一目录的外部改动会进入现场快照，应在运行前安排好操作时段。
- 保留既有 8 MiB P4 元数据输出、1000 个差异文件及命令超时限制。大项目建议将 scope 设为本轮需要修改的代码子目录。
- 单文件删除或创建不代表提交权限；平台始终不自动 submit。
- AltRoot 根据命令当前目录选择，依据 [Perforce 官方说明](https://help.perforce.com/helix-core/server-apps/cmdref/current/Content/P4Guide/configuration.workspace_view.multiple_computers.html)。已有 edit/delete 状态通过原清单 reconcile 更新，依据 [reconcile 命令说明](https://help.perforce.com/helix-core/server-apps/cmdref/current/content/CmdRef/p4_reconcile.html)。
