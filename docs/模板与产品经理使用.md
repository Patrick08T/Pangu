# 模板与产品经理使用

三类示例位于 `examples/templates`：产品经理（四种独立模式）、小范围代码修改、只读项目巡检。示例都是跨项目共享模板，不带项目 ID、连接、目录或运行输入；导入后先发布，再为目标项目创建新的绑定 Agent。绑定后不能修改项目。产品经理模型名由绑定时指定的项目连接版本替换。

## 导入、发布、绑定与执行

1. 管理者登记项目，设置 Worker ID、Git 来源及工作区根目录。先为项目创建并发布模型连接，`secret_ref` 只填写 `PANGU_SECRET_` 环境变量名，密钥保留在 Worker 环境。
2. `POST /catalog/import` 提交示例 JSON。唯一支持格式为 `pangu.catalog.v1`；每次导入创建新对象，不覆盖旧 ID。项目对象导出保留项目 ID，跨项目复用使用共享模板重新绑定，不通过编辑旧对象迁移。
3. `POST /catalog/{id}/publish`，请求 `{"revision":1}`。记录返回的不可变版本 ID。
4. `POST /versions/{模板版本}/bind`，提交 `project_id`、`name`；Eino 同时提交该项目的 `connection_version`。发布新绑定的 Agent，记录其版本 ID。
5. `POST /versions/{Agent版本}/run`，带 `Idempotency-Key`，正文为 `{"input":"运行输入"}`。产品经理的 input 是 `examples/product-brief.json` 的 JSON 字符串。相同键重试先查询已有请求，不换键重复发起。
6. 查询 `/requests/{id}` 与 `/runs/{id}`。完整工具证据在 `/runs/{id}/nodes/{node_run_id}/attempts/{attempt}`；详情中的 attempts 只含摘要。
7. `/runs/{id}/artifacts` 同时列出代码差异与报告。报告正文不塞入 16 KiB 节点结果，下载和 ZIP 使用已有产物接口。报告仅按文本展示，不自动发布到飞书或执行其中任务。

草稿导出：`GET /catalog/{id}/export`；固定版本导出：`GET /versions/{id}/export`。列表和版本列表使用 `offset` 翻页，每页最多 100 条。发布新版本不会修改旧 Agent、运行或定时计划。

## 产品经理输入与权限

`question`、`audience`、`market`、`time_scope`、`context`、`constraints` 必填，每项最多 16 KiB。不确定的信息明确写“未知”，不能省略必要上下文后假装完成。各列表最多 10 项。

| 字段 | 用途与边界 |
| --- | --- |
| public_queries | 用户明确同意公开发送给搜索服务的搜索词；模型只能选索引，不能拼接项目资料外发 |
| urls | 用户提供的公开 HTTPS 来源；仅 443 端口，不含凭据或片段 |
| documents | 允许读取的项目相对文件名；从本次运行的原始 Git 基准读取，不读取实时源目录、符号链接、凭据文件或未提交内容 |
| competitors / dimensions | 竞品分析必填；候选名称和比较维度，不把未知解释为没有 |

Worker 提供公开搜索、来源正文读取、项目资料读取、直接上游报告分页读取、报告登记五个工具。搜索端点固定为 Brave Search；`PANGU_SEARCH_API_KEY` 从 Worker 环境读取，预检查不发送收费搜索。没有搜索词时可仅用明确授权的网页或项目资料调研。

网页每次最多 2 MiB、抽取正文最多 64 KiB；项目资料最多 64 KiB；上游报告每页 16,384 个 Unicode 字符。公网连接在 DNS 解析后校验所有地址，直接连接已校验 IP，重定向每跳校验；不使用系统代理、Cookie 或站点登录。网页中的指令不能新增工具、来源、路径或搜索词。HTML 的脚本/样式不进入正文；正文仍属于不可信资料，不能据此宣称消除了模型幻觉。

每个 Eino 节点共享最多 10 次工具调用（失败也计数），单次最多 30 秒且服从节点总超时。来源失败会返回明确错误；报告只接受实际读取的来源。正文引用用 `[来源ID]`，平台将其保存为普通文本并附加地址、获取时间和内容摘要；禁止模型自行生成链接或 HTML。标题、正文与任务字段检查疑似凭据。

每节点只登记一份最多 1 MiB 的报告；报告和节点结果在同一 PostgreSQL 事务保存。结果回执丢失后重试会读取原报告，不重复调用模型；取消先持久化时拒绝发布新报告。已成功的上游报告保留。报告并行生成不锁住整个运行工作区。

## 四种模式与串联

- `research`：调研范围与方法、发现与建议；至少授权一个公开搜索词、网页或项目资料，且报告至少引用一个实际读取的资料来源。
- `competition`：竞品矩阵、定位差异；包含明确竞品和维度，可读取调研上游报告。
- `planning`：PRD、优先级与路线图、成功指标；资料不足列为假设或未知，不虚构人力和工期。
- `design`：用户流程、输入输出及异常边界、任务与依赖、验收条件；登记时必须提供 1–32 个任务，逐项包含范围、前置依赖、交付物和验收条件，平台校验依赖存在且无环。

四种模式均要求“结论、证据与推断、未知项”。模式决定执行行为，不能只靠修改提示词冒充另一种能力。

串联时创建工作流对象，`spec.flow.nodes` 使用四个**项目 Agent 发布版本**：

```json
{"nodes":[
  {"id":"research","agent_version":"替换为调研 Agent 版本 UUID"},
  {"id":"competition","agent_version":"替换为竞品 Agent 版本 UUID","depends_on":["research"]},
  {"id":"planning","agent_version":"替换为规划 Agent 版本 UUID","depends_on":["competition"]},
  {"id":"design","agent_version":"替换为方案 Agent 版本 UUID","depends_on":["planning"]}
]}
```

示例中的说明字符串必须替换为真实 UUID 后提交。每节点由 Hatchet 独立调度。下游工具只允许读取当前运行的直接上游报告；超过单页的资料要显式翻页，页数消耗工具额度。报告里的开发任务仅为交付物，不会自动执行。

## 代码类模板

修改模板默认不自动重试，减少重复执行项目命令的外部副作用；可在发布前明确调整为 0–2 次。验证命令由项目和输入明确给出，不接受网页追加命令。命令输出证据来自 CLI 事件，不把模型自述当测试结果。

只读模板设置 `read_only:true`，调用原生 `codex exec --sandbox read-only`。Worker 还检查尝试的文件差异，出现修改则拒绝发布检查点。此双重检查不等于跨操作系统账户的安全隔离；实际 Codex 沙箱能力仍需支持平台验收。

当前四模式链路已使用真实 Hatchet、PostgreSQL、Git 和 Eino，通过本地模拟模型端点验证。真实付费模型、Brave 搜索质量及人工采纳不在该测试的证明范围内。
