# Pangu 产品可用性审查

日期：2026-10-25。范围：当前本地产品的任务入口、配置、执行和结果查看。用户已确认本次调整；任务 1–6 已实现，任务 7 的自动验证已通过，本机页面验收另见文末。正式需求与范围见 [易用性 PRD](PRD-Pangu易用性.md)。

## 用户要完成的工作

用户描述一个项目任务，选择合适的助手，得到可以阅读、下载和继续处理的结果。开发者还可以复用助手、设置定时任务和编排多个步骤。首先保证单个任务能顺畅完成，再让用户进入高级能力。

目前已经实测 Worker、Eino 和项目预检可通过，历史上也有成功运行。问题集中在产品流程：用户必须先理解内部配置对象，结果页又把执行机制放在交付物前面。一次技术冒烟成功不能作为产品可用的验收标准。

## 竞品对决策的启发

- [Dify 快速入门](https://docs.dify.ai/en/quick-start) 将模型配置、应用设计与最终输入表单分层，并允许资料和语气等信息选填。Pangu 应借鉴使用与配置分层，不要求普通用户操作发布版本。
- [Flowise Agentflow V2](https://docs.flowiseai.com/using-flowise/agentflowv2) 提供聊天或表单作为启动入口，编排位于其后。Pangu 应先支持简单任务入口，不为了简化外观新增一个聊天后端。

## 可独立执行的任务及验收

| 顺序 | 任务 | 边界与验收 |
| --- | --- | --- |
| 1 | 调整信息架构与首页 | 登录后能看到新建任务；管理入口按角色开放；已有链接仍可进入原有功能，不删除业务数据 |
| 2 | 合并助手和版本选择 | 只展示当前项目未归档、已发布的 Agent 或工作流；单一选项自动选择；运行仍固定真实版本；空列表提供具体准备入口 |
| 3 | 简化产品经理输入 | 只填目标即可启动规划或设计；调研与竞品分析仍校验其必要信息；空白来源不被当成授权；通用 JSON Schema 的必填语义保持正确 |
| 4 | 合并检查与启动 | 点击一次开始，校验失败原地提示且保留输入；预检失败不创建任务；重复点击不重复提交；提交结果未知时保持同一请求键 |
| 5 | 结果优先的任务详情 | 完成后首先看到输出和产物；待审批操作始终可见；取消、失败、过期有明确说明；日志和定义可以展开 |
| 6 | 改善记录与管理指引 | 记录用可读任务标题；设置集中；缺少账号、搜索或可用助手时给出可操作的下一步 |
| 7 | 完整场景验收 | 覆盖已配置项目的一次任务，以及无助手、空输入、预检失败、重复点击、权限不足、失败运行和过期产物；真实模型调用单独记录是否执行 |

## 不以简化为由移除的能力

项目隔离、飞书身份和成员权限、固定运行版本、幂等提交、工具和联网授权、原始项目保护、节点恢复及审计继续保留。它们应由产品正确执行，而非要求用户在日常操作中理解全部机制。

本轮不新增工作流引擎、不增加模型供应商、不实现即时聊天和自动推断授权范围、不购买搜索服务。先用现有 Hatchet、Eino、Codex 和 API 完成上述流程。

## 实施与验收记录

2026-10-25 已完成并部署本轮功能。新增当前项目可运行助手查询，直接读取当前发布版本；产品经理背景改为选填；助手准备使用角色表单；任务入口合并预检与提交；详情优先展示报告；任务标题在读取时生成，不写入长期摘要。没有删除业务数据或更换账号。

自动验证：前端 22 个测试文件共 44 项测试通过；OpenAPI 类型同步、TypeScript 和 Vite 构建通过；Go 全量串行测试（含独立数据库）、函数长度检查、`go vet`、程序构建及受控 Codex 源码校验通过。已覆盖单助手自动选择、预检失败不提交、未知提交保持原键、连续点击、无助手入口、项目权限、发布版本选择、目标必填、报告自动预览及按需日志。原生 Codex 独立审查未发现新增中高风险。

- 设置中的运行环境显示 API 在线、产品数据库就绪、Hatchet 编排已注册。此项不等同于新的模型执行验收。
