## 接入判断

FlowGram 验证代码放在独立实验工程中，不改变生产依赖。只有数据无损、React 19 可用、编辑行为不倒退，且能减少当前表单与变量开发维护工作时，才替换正式画布。否则保留现有 React Flow，直接交付交互改进，并留下可复现的实验和结论。

正式产品维持现有蓝白工作台：左侧助手、中央画布、右侧配置。把用户最常用的职责、输入来源、运行结果放在前面；高级路径和执行细节按需展开。继续使用现有组件和样式，不新增设计系统。

## 影响范围与边界

- 生产改动：`web/src/flow` 的配置与变量表单、`web/src/catalog/agent.tsx` 的输出字段表单、`web/src/runs` 的运行图和诊断组件、相关测试与样式。
- 实验：独立 `experiments/flowgram`，保存完整 Pangu 数据并验证编辑器导入/导出，不接入执行引擎。
- 不变：数据库和公开 API、版本发布规则、Hatchet 调度、模型凭据、项目目录和工作区安全策略。
- 不增加循环、子流程、互斥分支汇合、多人协作；不把 Eino 的完整输出伪装成逐 token 流式输出。
- TDD 先覆盖字段选择、失效引用和节点切换诊断，再实现。最终使用已获授权的 Codex 原生 Agent 独立审查。

## 采用结论与验收记录（2026-10-26）

FlowGram 1.0.16 在本机 React 19.3.1 + Vite 8.3.5 的 StrictMode 开发环境中报 `FlowRendererRegistry` 重复绑定错误。关闭严格模式的对照实验能够真实渲染并往返样本数据，但不满足当前工程直接接入门槛。本轮保留 React Flow，不修改正式依赖或关闭 Pangu 的严格模式。详见 [可复现实验](../experiments/flowgram/README.md)。

已交付：

1. 助手输出字段通过表单定义；节点显示固定版本职责、产品经理方式和文件能力。管理员可查看 Eino 对应的 Codex 账号模型说明；普通成员不请求受限连接配置。
2. 变量以可读字段名和中文类型选择，自动填写实际路径与类型；只允许流程输入及直接上游，失效引用保留供修正。发布版本可展开原始路径，但不可修改。
3. 运行图点击节点后集中查看真实输入、输出、错误和工具证据；尝试选项只取实际落库记录，支持分页，不从 Hatchet 排队计数推断已执行。

验证：

- TDD：字段选择、类型切换、失效引用、输出表单、权限门控、只读路径展开及排队节点有先失败再通过的记录；补充历史分页回归。前端全部 29 个文件、74 项测试通过。
- 实验 4 项测试与独立 Vite 构建通过；生产 OpenAPI 契约、TypeScript 和 Vite 构建通过；Go 应用重新构建并部署至本地 8081。
- Codex 原生独立审查完成，修复连接权限、只读展开及虚构尝试三项问题，最终无新增中高风险。
- Chrome 验证变量选择、保存、刷新恢复、发布示例 v2、只读路径查看；真实历史成功任务能显示输入、输出及实际工具证据；未开始执行的历史节点正确提示，控制台无错误。
