# 竞品与技术决策

> 2026-10-28 归属模型更新：角色、工作流和模型连接在工作空间共享，运行时选择项目；模型连接无需项目授权登记。本文旧的模板绑定/项目连接设计仅保留为历史背景，当前以 [共享角色与工作流](../specs/共享角色与工作流.md) 为准。


面向下一阶段产品定位、使用体验与优化优先级的比较，见 [2026-10-24 竞品对比与优化建议](竞品对比与优化建议-2026-10-24.md)。本文继续记录现有实现的技术取舍，不将新建议视为已确认需求。

用户于 2026-10-23 授权按任务卡持续实施：遇到不确定项先调研竞品和官方实现，结合本项目选择方案，不重复确认已决定的产品取舍。真实外部资源和人工验收仍需如实记录，不能用模拟结果代替。

## 运行状态与取消

Temporal 将取消请求与最终结束区分，允许执行器完成清理；Hatchet Go SDK 的 Cancel 同样是请求取消，返回的任务 ID 不能证明操作系统子进程已经退出。实测 v0.110.5 仅取消根运行后，执行中的子节点20秒仍未收到 context 取消。Pangu 因此持久记录取消意图，显式取消根及直接子节点，并每秒对账；节点尝试开始与取消记录使用同一个数据库事务锁，取消之后禁止新执行器启动。实际执行函数返回后记录停止证据，不根据 HTTP 202 直接报告 cancelled。进程崩溃导致缺少停止凭据时保留不确定状态，后续由工作区恢复协议补证。

- [Temporal 工作流操作](https://docs.temporal.io/tctl-v1/workflow)
- [Hatchet Go Runs SDK](https://docs.hatchet.run/reference/go/feature-clients/runs)
- 本地固定版本：Hatchet v0.110.5，`sdks/go/features/runs.go`。

运行查询使用产品 DTO，根运行限定当前命名空间的工作流 ID，子节点通过父任务 ID 查询。分页固定 since/until，默认 20、最多 100；状态筛选期间状态仍可能变化，客户端需要刷新第一页，不能把 offset 分页描述为数据库事务快照。

## 幂等提交

Hatchet 的工作流幂等约束支持表达式、TTL 和冲突时返回已有运行 ID。Pangu 将持久请求键与该能力结合，对提交结果不确定的请求先按键对账，不盲目新建第二次执行。具体固定版本实验和故障证据由 R12/R13 记录。

- [Hatchet Go 工作流与幂等配置](https://docs.hatchet.run/reference/go/runnables)
- 本地固定版本：`sdks/go/e2e/idempotency_test.go` 与 `sdks/go/workflow.go`。

## 单个 Cron 的暂停

Hatchet 的工作流级暂停影响该工作流全部触发来源。Pangu 多个计划共用一个编排器，因此单计划暂停在计划记录和该计划的触发器上实施，不能直接暂停公共工作流；在途运行继续。

- [Hatchet 暂停工作流](https://docs.hatchet.run/v1/pausing-workflows)

## 项目与尝试的文件隔离

GitHub Copilot 会话采用独立工作空间；VS Code 的 Agent 会话支持 Git worktree。Pangu 沿用用户已确认的独立 clone，使用 Git 官方 `--no-local --no-hardlinks`，避免借用源仓库对象。目标路径按解析后的实际路径校验，防止 junction 把运行目录指回源项目。

每次 Codex 尝试使用单独 clone；成功后在 Worker 持有的仓库中创建 Git 检查点，并在同一 PostgreSQL 事务中发布检查点和结果。失败目录保留用于诊断但不进入后续尝试；重启发现已有成功检查点时读取已有输出，不重复调用模型。发布使用运行级数据库锁和前置提交比较；连接丢失的旧执行器不能通过新连接提交陈旧结果。新工作副本始终从已发布检查点建立。

这是对隔离成本与恢复可靠性的取舍：本地磁盘用量增加，后续由保留期清理。不能撤销 Agent 已经对外部系统产生的副作用。Git 快照使用 Worker 自己的 `.git` 配置，不使用 Agent 可修改的 hooks、filters 或 Git 配置。

- [GitHub Copilot 独立会话工作空间](https://docs.github.com/en/copilot/how-tos/github-copilot-app/agent-sessions)
- [VS Code Agent 会话隔离](https://code.visualstudio.com/docs/agents/run/agents-window)
- [Git clone 官方说明](https://git-scm.com/docs/git-clone)

## 配置版本与字段映射

Dify 将编辑草稿与发布历史分开，Langfuse 提供不可变版本及可移动标签。Pangu 采用草稿修订号和不可变发布版本；运行、项目 Agent 和计划只引用明确版本 ID，不引入隐式 latest，也不使用配置缓存。共享模板不带项目连接，绑定时创建新项目 Agent，数据库约束禁止迁移所属项目。

- [Dify 工作流版本与复用](https://www.dify.ai/workflows)
- [Langfuse 版本数据模型](https://langfuse.com/docs/prompt-management/data-model)

Dify 的结构化输出使用 JSON Schema。Pangu 首版采用可验证的基本子集：对象、数组及标量；对象拒绝未知字段，限制深度与字段数，不支持远端引用或脚本。校验复用已安装的 jsonschema v6，映射仅允许 `$input` 或直接上游的 JSON Pointer，缺失或类型错误直接失败。

- [Dify 结构化输出示例](https://docs.dify.ai/en/guides/application-orchestrate/creating-an-application)
- [jsonschema Go 官方包文档](https://pkg.go.dev/github.com/santhosh-tekuri/jsonschema/v6)

## Windows 恢复凭据

Windows 的 `Local\` Job 名称按 session 隔离。停止凭据同时记录进程创建时间与 session；恢复查询不按 PID 单独排除记录，避免 PID 复用。不同 session、身份缺失或无法查询的记录保留未知状态，不声称进程已经退出。

- [微软内核对象命名空间说明](https://learn.microsoft.com/windows/win32/termserv/kernel-object-namespaces)

## 产品经理调研工具

Dify 将出站请求经过 SSRF 代理。Pangu 首版没有增加独立代理服务：网页读取在请求层校验 HTTPS/端口、每次 DNS 解析结果和每次重定向，直接拨号到校验后的公共 IP；禁用代理、Cookie 和跨域凭据继承。工具输入只接受已登记来源 ID 或用户明确授权的查询/文档索引，页面正文不能产生额外授权。

公开搜索使用 Brave Search 的固定 web search 接口，密钥仅在 Worker 环境读取；不把模型临时生成的项目内容拼成搜索查询。四种产品经理模式复用这一组工具，报告需要平台可验证的来源 ID、时间及未知项，长报告保存在产品数据库并作为受项目权限保护的产物导出。

- [Dify SSRF 代理实现](https://github.com/langgenius/dify/blob/main/api/core/helper/ssrf_proxy.py)
- [Brave Search API](https://api-dashboard.search.brave.com/documentation/quickstart)

## 飞书认证与授权归属

Apache APISIX 的飞书认证插件展示了授权状态与浏览器会话的绑定；当前飞书文档已将旧 v2 token 接口标为历史版本。Pangu 使用官方 v3 表单接口和配对 PKCE，登录状态 5 分钟、单次消费；后端读取 open_id/tenant_key，飞书令牌仅用于当次身份查询，不保存或交给浏览器。Pangu 会话固定 12 小时，数据库只存随机令牌摘要；会话请求使用 HttpOnly Cookie，修改操作检查 Origin 和 CSRF。

身份只来自允许的飞书应用/租户，首位管理员必须明确配置 open_id；之后由管理者登记项目成员。每次授权读取当前数据库，API Token 叠加项目/操作范围限制，角色变化不依赖缓存刷新。项目管理员与命名空间管理员区分，禁用 Pangu 用户由命名空间管理员执行。

禁用、成员变更、Token 发放、新建/编辑计划和触发认领共用命名空间身份事务锁；禁用会撤销已有会话/Token 并暂停未来计划，已被认领的触发继续使用接受时的快照与创建者。重新启用不会自动恢复计划或撤销过的凭据。授权已通过的普通在途请求可以完成；后续请求立即读取新权限。

- [飞书当前 v3 Token 接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/get-user-access-token-v3)
- [飞书授权入口](https://open.feishu.cn/document/common-capabilities/sso/api/obtain-oauth-code)
- [飞书身份信息](https://open.feishu.cn/document/server-docs/authentication-management/login-state-management/get)
- [APISIX 飞书认证源码](https://github.com/apache/apisix/blob/master/apisix/plugins/feishu-auth.lua)

## 模型凭据与端点的授权

Windmill 对凭据引用单独执行资源权限检查，引用名本身不等于访问权。Pangu 使用主机管理员的 `PANGU_CONNECTION_GRANTS` 原始 JSON 登记项目 ID、完整模型端点、凭据环境变量名及允许模型列表。连接发布与每次解析都重新校验；项目管理者不能通过连接 API 变更这份登记。模型 HTTP 客户端禁止重定向和系统代理，避免把授权凭据带到未登记地址。

默认 `OPENAI_*` 由主机管理员显式提供，属于部署共享的默认模型服务；端点不可由运行 JSON 覆盖。需要独立项目凭据时使用发布的连接版本及上述授权登记。没有登记的项目连接拒绝调用，不回退默认凭据。

- [Windmill 变量与凭据权限](https://www.windmill.dev/docs/core_concepts/variables_and_secrets)
- [Windmill 资源引用与历史](https://www.windmill.dev/docs/core_concepts/resources_and_types)

## 冷备份与本地恢复

PostgreSQL 的文件系统备份要求一致的数据目录，首版采用允许维护窗口的完整停机复制；同时保存两个数据库、Hatchet 密钥和托管工作区，并记录文件长度与 SHA-256。恢复仅写全新目录，禁止覆盖原库和跟随 junction/symlink。真实独立副本已验证配置版本、请求、Hatchet 历史与产物；完整操作见 [运行与恢复](运行与恢复.md)。

Hatchet 的嵌入式模式面向本地开发与 CI。其多个数据库池默认上限相加可挤占内嵌 PostgreSQL 的 100 个连接，因此本地脚本将普通池设为 10、DDL 池设为 2；真实副本启动已验证。正式部署规模扩大时使用官方独立服务部署，不能把本地副本测试解释为高可用验证。

- [PostgreSQL 文件系统备份](https://www.postgresql.org/docs/current/backup-file.html)
- [Hatchet 本地部署](https://docs.onhatchet.run/v1/running-locally)
- [PostgreSQL 连接上限](https://www.postgresql.org/docs/current/runtime-config-connection.html)

## Codex 专用配置与工具限制边界

Codex 当前支持独立 `CODEX_HOME`、不受信任的项目配置和功能开关。Pangu 强制采用管理员指定的独立目录，仅继承操作系统必需环境，拒绝个人配置目录、工作区内配置目录；应用、插件、两代子 Agent、技能自动发现/安装关闭。管理员在独立 `config.toml` 中登记允许的技能/MCP，不自动安装依赖。真实 CLI 0.163.0 的配置检查验证，即使专用文件启用多 Agent 和插件，命令行限制也会覆盖。

原生 CLI 没有统一的最大工具调用配置。官方 Hooks 文档明确部分回调错误可放行，`write_stdin` 不再次执行 PreToolUse；因此仅增加 hook 或监听输出后终止，都不能证明“第 11 次调用绝不会执行”。App Server 动态工具接口也不能直接推断为可拦截全部内置工具。C08 因此采用本文末尾的固定版本原生补丁，单独验证次数与单次时限。

- [Codex 配置](https://learn.chatgpt.com/docs/config-file/config-reference)
- [Codex Hooks 与工具覆盖](https://learn.chatgpt.com/docs/hooks)
- [Codex App Server](https://learn.chatgpt.com/docs/app-server)

## 数据与幂等摘要分层

按已确认规则，临时输入、指令、事件和产物 30 天到期；请求标识、输入摘要及运行关联保留 90 天。Pangu 清理提交/触发快照时只留下版本/来源标识，版本回执通过输入摘要比较，重跑回执通过来源和创建者匹配，避免为了幂等保留整个临时输入。有效发布配置属于独立长期配置，不随运行清理。

Hatchet 官方文档的租户保留期与固定版本源码中的 core/OLAP 分区保留不是同一层。0.110.5 的 OLAP 清理同时覆盖运行和 payload，现有 API 未发现单条 payload 删除能力。参考 Temporal 将运行查询数据与执行历史区分的方式，Pangu 将 Hatchet core/OLAP 设为 720h，独立保存已确认终结的无正文摘要至 90 天，不修改 Hatchet 内部表。

归档每分钟轮转检查 100 条，读取已完成运行时也保存摘要；输入、输出、事件、错误正文均不进入摘要。列表以产品提交记录分页，终结状态用原始归档源，活跃状态实时查询 Hatchet；未知项不破坏整页。Hatchet 按插入日分区清理，可能早于结束满30天，因此详情的归档回退不附加结束时间门槛；工作区基准是否可重跑仍按产品清理记录判定。归档器停止超过远端保留窗口前，必须先完成备份，否则未归档终态只能显示未知，不能猜测成功。

- [Hatchet 数据保留](https://docs.onhatchet.run/self-hosting/data-retention)
- [Temporal 查询存储](https://docs.temporal.io/visibility)

原生 Codex 工具限制采用固定版本小补丁：在统一工具注册表执行前原子计数并启动独立计时器，原生命令强制同步结束。详见 [受控构建](../runtime/codex/README.md)。这保留原生执行器，同时消除 Hook 不完整覆盖和事后观察的窗口；Pangu 对缺少能力协议的普通 CLI 明确拒绝。新增构建维护成本由固定提交、依赖锁、独立测试及真实本地端点回归约束。

固定源码与本地 SSE 实验发现，上游工具 `Fatal` 在收尾阶段可被记录后继续模型循环，因此限制失败使用独立退出码 87，单工具计时器使用 86，由 Worker 确认整组进程停止再返回失败。模型目录可优先选择 Code Mode，受控模式必须在工具模式选择处强制 Direct；Windows 未显式配置沙箱时可能将可写策略降为只读，因此使用官方非提权沙箱，保留只读模板的原策略。这些判断来自实际文件写入/拒绝实验，不以工具名称或模型自述替代执行证据。
